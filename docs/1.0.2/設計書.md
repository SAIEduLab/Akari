# あかり1.0.2 設計書

## 実装するもの

日本語の文節と役割を読み、意味モデルを作り、その同じモデルを文とブロックで編集する。子どもの作文を古い命令へ翻訳させる画面を追加するだけではない。言語・対象・イベント・編集構造は必要に応じて再設計する。

能力を減らさないこと、新しい二つの表示の全機能相互互換、mainを更新せずdraft PRで止めることを守る。74命令・153スキーマ・260能力の基準集合は追跡の出発点であり、内部構造や件数を固定する上限ではない。自然な作文と全能力を基準に現在の構造を定める。

本書は実装前の契約。製品の変更・ゲート合格を主張する文書ではない。文書・静的作業はクラウド、ユーザーPCは許可されたChromeの独立実操作QAだけに使う。

## 1 表層 役割 意味 実行を分ける

次の四段階を明示する。

1. 原文/CST：句読点、かな・漢字、語順、名詞の区切り、助詞、活用、コメント、各節の位置を保持する
2. 役割木：だれ、変更先、内容、方向、量、時間、開始条件、継続条件、反復範囲、引数の名前などを持つ。未完や複数の解釈候補も保持できる
3. 意味AST：実行対象と操作、式、制御構造、イベント、手順、値を求める定義を一意に持つ。選択されていない解釈を実行へ渡さない
4. 実行IR：スケジューラーの命令、待機、状態ルール、素材参照、範囲と診断位置への対応を持つ

ブロックは役割木と意味ASTの編集ビュー。原文へ戻るための情報を持つが、別の隠れたプログラムを保存しない。文字列の置換で命令をそれらしく翻訳する層を作らない。

## 2 共通文型レジストリ

実装の共通台帳には、少なくとも以下を持たせる。パーサー、ブロック、候補、検索、整形、入力支援、教材例はここを参照する。型判定とruntimeの安全検査は独立実装で照合する。

```text
SentenceForm
  id                 安定した文型識別子
  intent             子どもがしたいことの説明
  semanticOperation  対応する能力
  roleSlots          名前、種類、必須/任意、数・単位・所属・参照制約
  clauses            有効な文節配置と助詞
  verbForms          終止形、て形、条件形、連用形など実際に許す文字列
  nounForms          引用/値/答え/名前の格を含む名詞句
  acceptedReadings   この語に限ったかな形
  evaluationOrder    役割ごとの評価順
  allowedContexts    対象の種別、イベント、手順、値の定義、局所制約
  render             標準文とブロックの同じ文
  preview            状態を変えない説明と範囲表示
  errors             足りない役割、重複、単位、曖昧さごとの説明
  positiveExamples / negativeExamples / traceIds
```

役割の並べ替えはレジストリが列挙する有限の文節集合の順列として定義する。例えば移動は対象/方向/量/動詞であり、横/縦の数を左右の出現位置だけで読まない。可変の名前や式は先に区切ったトークンとして扱うため、名前の登録数で文節境界が変わらない。

単純な命令列の「進んで」と、条件の「押されていて」は異なる構文位置。形容詞の「小さくて」、名詞述語の「以上で」、引用の「と言う」、名詞句の「を言う」は別の生成規則を持つ。文末文字列の一括変換で済ませない。定義の「変数を作り、最初は…」などは、完全な複合文型として登録してよい。

## 3 構文の閉じ方

以下はメタ記法であり、利用者に覚えさせる構文ではない。全終端文字列は仕様書の表・付録A・語彙レジストリに限定する。

```text
projectDocument = { eventDocument | continuousRule | callableDocument }
eventDocument   = eventHeading (newline indent suite dedent | flatSequence)
suite           = { comment | statement }
statement       = flatSequence | inlineRepeat | ifBlock | repeatBlock | listEachBlock
flatSequence    = [discourseMarker] clause { teConnector clause } [period]
clause          = [actorPhrase] registeredActionForm
ifBlock         = ifHeading suite [elseHeading suite]
repeatBlock     = countHeading suite | whileHeading suite
                | untilHeading suite | foreverHeading suite
inlineRepeat    = flatSequence "ことを" count "回くり返す"
listEachBlock   = listEachHeading [binderDeclaration] suite
condition       = atomicPredicate | fluentTwoPredicate | explicitBooleanExpression
actorPhrase     = actorName plus registered subject/patient/causative particle
quantity        = scalarExpression plus one registered role-unit
continuousRule = stateClause actorPhrase direction speedClause continuousVerb
```

`inlineRepeat`の内部は非制御の命令列に限る。より深い入れ子は字下げにする。二つの繰り返し見出しやelseを同一行に詰め込んで優先順位を推測しない。句点で閉じた複数の独立文は、字下げが同じsuiteの順序として扱う。

解析の順序：

1. 文字列/エスケープ、名前、コメント、括弧、リストを字句解析し、原文範囲を保持
2. 字下げと、括弧外の句点・文型固有の区切りを解析
3. できごと・定義・継続状態・条件・反復の見出しを識別
4. 述語と助詞の組合せから候補文型を限定し、各役割を一度だけ埋める
5. 条件接続、命令接続、値の名詞化をそれぞれの位置で解析
6. 一意なら役割木を作り、名前や型、単位、所属、対象の実在を意味検査
7. 0候補なら不足・未対応、複数候補なら曖昧として保持し、実行を止める

曖昧な候補に順位を付けて一位を黙って実行しない。「入力した文は正しい日本語ですが…」を毎回定型で出す必要もない。実際に足りない役割を、原文の該当箇所と候補の動きで示す。

### 字句の境界

数の核はASCII換算した `[0-9]+(?:\.[0-9]+)?`、符号は別の単項演算。半角/全角の対応表は固定し、指数表記や漢数字を推測して追加しない。全ての有限数は計算と数値の形式で扱えることを確認し、表示丸めで値を変えない。

囲った名前は1〜32コードポイントの名称を一つのトークンにし、制御文字・改行・区切り文字を禁止する。裸の名前の境界は、確定した文型レジストリの助詞/演算子/句読点/単位接続語から作る固定表を使う。固定表には少なくとも「は/が/を/に/へ/の/と/で/から/より/まで」、括弧、句読点、演算子を含む。名前の実在や候補数で区切り表を変えない。衝突する名前も【名前】で使え、候補挿入は必要な囲みを付ける。区切り表そのものもfixtureとして固定し、文型追加による影響をレビューする。

文字列は先に閉じるまで読み、仕様の三つのエスケープだけを解決する。元の文字位置と対応するoffsetを保持する。内部のJS offsetはUTF-16、利用者へ示す行/文字位置とDOMの選択範囲への変換は明示し、絵文字・結合文字で試験する。非保護領域の空白や全半角の正規化で原文への対応を失わない。

### 式

有限数、文字、条件の答え、単層リスト、名前、所属、センサー、関数呼出し、全組込みを保つ。累乗は右結合で単項符号より強く、その後は乗除、加減、比較、否定、AND、OR。日本語で混ぜたAND/ORにこの優先順位を無断で押し付けず、自然な複合文では括弧を求める。明示的な数式/条件式では定義済み優先順位を使える。

名詞句には、引用内容、データの値、関数で求めた答え、条件の答え、リストの項目などの区別を持つ。`「こんにちは」と言う` と `点数の値を言う` を、評価後の型を見て適当に選ぶのではなく、構文上の格として持つ。式を構築する全能力は、文型を自然にするために削除しない。

## 4 実行対象の解決

### 4.1 原則

EventContextに開始対象とイベント情報、CallableFrameに受け取る値・局所データ・呼出し時の対象を持つ。構文のsuiteごとにtopicActorを持つ。子のsuiteは親のtopicActorを受け継ぎ、子の解析終了で親へ戻る。

対象を変えるのは、登録された動作文の動作主/被動作対象の明示だけ。条件式の人物、接触相手、距離を測る相手、データ所有者、知らせの宛先、素材名を読んだだけではtopicActorを変えない。

```text
作品を動かしたとき、ねこは、
  もしいぬがねこにふれていれば、
    「さわった」と言う。  ※ ねこ
  前へ10歩進む。          ※ ねこ
```

この条件の「いぬ」は状態を調べる主体、「ねこ」は接触相手であり、後続命令の主語指定ではない。`いぬの点数の値を言う` のデータ所有者も、発言する対象を変えない。

意味ASTの各動作文にActorRefを確定して付ける。省略主語はruntimeの最後の実行対象を読む仕組みにしない。ActorRefは現在の呼出し対象を表す相対参照、または実在する元の部品のIDへ結び付く名前参照。字句解析段階でIDの実在によって区切り方を変えない。

### 4.2 原子的な文と時間をまたぐ動作

明示対象付きの文は同じtaskの中で作用先を切り替える。taskそのもののID、開始イベント、通知待機関係、呼出しスタックは変えない。イベントを自動送信して代用しない。

一つの文の式評価は、その文のeffectiveActorを使う。自分のデータ、横位置、向き、接触判定はその対象に属す。局所変数/引数/反復項目と作品データはそれぞれのスコープを保つ。`いぬの横位置`等の明示参照はActorQualifiedReadとして別対象を読み、topicActorに影響しない。

移動・音待ち・質問・手順など時間をまたぐ処理は、開始時のActorRef解決結果を継続状態へ固定する。画面上で選択対象を変更したこと、次の節の対象、別taskの実行により途中で対象がすり替わらない。対象が削除された場合は基準のruntime安全規則で終了/診断し、近い名前の別対象へ付け替えない。

手順内の明示対象はその手順のsuite内で有効。戻ると呼出し元のtopicActorへ戻る。名前指定のねこは元のねこ、分身イベントの相対参照はその分身。これを保存・player・デバッグ表示まで同じ参照モデルにする。

### 4.3 中核runtimeの改修注意

基準実装の多くの操作はctxだけでなくtask.runtimeIdを直接参照する。ctx.actorだけを差し替える小修正では、見た目の変更・重なり・ペン・入力欄・クローン・手順・状態表示で対象が分裂する。作用先を一つのExecutionSubjectとして渡す構造へ整理し、全操作の参照を監査する。

StopTHISはtaskを止め、StopOTHERSは作品内の他taskを止める。作用先がいぬになったからといって、停止対象をいぬのtaskだけへ狭めない。背景・全描画消去・音全停止などの作品全体への作用も維持する。

## 5 移動と継続動作

### 5.1 一回の移動

前/後ろの移動は現在の方向に沿った変位。上下左右は画面軸に沿った変位で、向きは変えない。`右を向く` は絶対方向、`右にN度回る` は現在方向からの回転。`2秒かけて右へ40歩動く` は、開始位置から右40歩の地点まで2秒ですべる一回の移動とする。期間の途中で再び開始位置を取り直さない。

既存MOVE/GOTO/GLIDE等へ下げる場合でも、追加文型の意味と原文の役割を失わない。方向移動を「向き変更＋前進」に下げるのは禁止。ペンを下ろしたときの線、中心/左上の座標関係、回転・拡大を含む外接長方形の接触、距離の中心間測定は基準と一致させる。

### 5.2 継続状態の制御

ContinuousRuleは、作品レベルのruleId、条件、対象、方向、速度を持つ。一つのruleId×対象IDに1つの制御状態だけを作る。通常のkeyDownハンドラーの多数のwhileタスクへ展開して、離し直しで重複させない。

制御状態はINACTIVE、ACTIVE、CANCELLED_UNTIL_FALSE。初回と各入力変化で状態を更新する。ACTIVE区間の開始時に速度式を一度評価し、入力イベント時刻で区間を分けて積分する。方向が前/後ろなら回転イベントでも区間を分ける。異なるルールの変位は合算する。

画面のrequestAnimationFrame回数は演算回数の基準にしない。論理刻みの格子は作品開始時に固定し、描画ごとに刻みの位相をリセットしない。論理時計上の時間を用い、積分は1ステップ最大1/60秒の区間へ分割する。長いdtを一回の大移動として扱わない。入力時刻・回転・停止などの境界でも区間を切る。負のdtは受け入れない。

一時停止中の時間は積分しない。再開時はlastTimeを再開時刻へ合わせ、停止時間を取り返すような移動をしない。フォーカス喪失でキー解放が取得できないときは、キー状態を解放し、押しっぱなしを残さない。バックグラウンド復帰による大きなdtも、表示を再開しただけで長距離移動にならないよう明示的な一時停止状態として扱う。通常の時間待ち/音/手順の論理時計と同じ停止規則にする。

コマンドと連続制御は、入力処理→区間の積分→その時刻で準備済みの命令という固定フェーズで実行する。対象の位置を書き換える命令が入れば、その時刻からの次区間の開始位置になる。独立したテスト時計で、描画頻度が違っても同一トレースとなることを確認する。

## 6 時間と非同期の意味

一文の「て」連結は一つの巨大な原子処理へ束ねない。各節は通常の1命令として公平なスケジューリングの単位を持ち、待ちで他taskが進む。接続によって基準より他の実行を飢餓させない。

音はSTARTとPLAY_TO_ENDを分離する。標準語「鳴らす」を後者、「鳴らし始める」を前者へ割り当てる。これは明示的な新しい表層契約であり、旧試験の同じ文字列をそのまま別結果へ追認するやり方はしない。旧START能力の試験は新しいSTART文型へ移して、開始後すぐ次へ進む意味の期待値は維持する。

通知の直接の受け手集合を送信時に固定し、その集合が全て終わるまで待つ能力を維持する。二文の「その知らせ…待つ」には、同じsuiteの直前の送信ノードへの明示的な参照を付ける。runtimeの全体変数「最後の通知」を読ませない。後続に対応する待機がある送信だけが群IDを作り、後続待機はその群IDだけを待つ。繰り返し内では各送信回を別IDにし、同じノードの前回の群と混同しない。群の完了・待機による消費・送信側の終了/取消で参照を回収する。送信と待ちの間に実行できる他taskや単一命令ステップを隠して一命令へ潰さない。

条件待ちは現在状態である。次の新しい押下を求める作文は、最初から押されている状態で解除してはいけない。本規格では、解放まで待つ→押下まで待つという二文の候補を示し、利用者がその動きを選んで確定する。未確定の未来待ちを普通のWaitUntilへ黙って変えない。

## 7 名前 引数 型 単位

引数の名前は文型解析後に定義へ結び付ける。「高さを30として」は代入ではなく、この呼出しの受け取り値の指定。引数名の順序を変えてもどの値が何かは名前で決まるが、値を評価する順序はソースの記載順を保つ。定義の引数順への整列は値を評価した後に行う。位置引数形は記載順＝定義順。

定義名は任意の名詞/動詞句を名称として囲って扱う。汎用の呼出しは「【増やす】という手順を行う」のようにし、語尾から活用しない。短い呼出し文は利用者が定義に登録した完全一致の別形。名称の追加で既存の組込み文型の区切り方が変わらないよう、衝突を定義時に拒否する。文型は解析できたが未定義の名前は、そのまま編集可能な参照として保持する。

Booleanは数や文字と別型。条件の述語は文脈別に生成し、値として保存するときだけ「条件の答え（あてはまる/あてはまらない）」を生成する。内部真偽を「あてはまる」という文字列へ置き換えない。型表示・値の表示・コードのリテラルは同じものではない。

数量は数値ASTと、役割/単位の注釈を持つ。歩・秒・度・回・番目・点・個・％・Hzを有限に認識する。単位なしの数や数式は全て保つ。名前から「点数だから点」と推定しない。単位付きデータの比較/加減の不一致は静的に分かれば静的診断、動的にしか分からなければ実行前の値検査で拒否する。単位を無断で換算しない。

数量の内部表現は数値の大きさとunit tagを持つ数の値として統一する。未注釈の数はunit=null。宣言側のexpectedUnitは別の任意制約であり、値のコピーの代わりにはしない。局所・引数・返り値・リスト・snapshot・deepCopy・凍結・valueText・sameValue・数値演算・保存validatorまでこの表現を扱えるよう更新する。単位のない数の既存能力を削減しない。

`UnitlessRead(value)`をコードの「（式）の数だけ」と同じブロックへ対応させる。元の値を変更せずmagnitudeだけを返す。全演算の単位伝播は仕様1.2bの有限表を実装し、未定義の複合単位を勝手に生成しない。単位なしを動作/演算の既知の単位で解釈する場合は、その役割をブロック/コードの値説明に表示する。単位換算は行わない。辞書外の単位の文字を捨ててnumericへ通さない。

宣言の単位設定はEditorTransactionだけで行い、runtimeからprojectメタデータを書き換えない。未知の動的単位はruntimeの型検査で診断する。UNIT-ROLESには、代入→リスト→引数→返り値→演算→保存/playerの経路を通す試験と、各段階の不一致・単位なし・明示的除去の反例を含める。

数値の精度、範囲、演算の結合、負数のAST表現は再設計できるが、有限数・全演算の結果・境界・診断を独立の基準で照合する。入力欄の便宜のために任意の式をリテラルへ書き換えない。

## 8 全能力の対応

付録Aは全74命令、付録Bは全153の基準ブロック、付録Cは260能力の新契約との対応。各行について実装時に、新ノード/レジストリID、コードfixture、ブロックfixture、意味trace、対象/文脈、保存/playerを記入する。単に同じIDがあることを能力維持の証拠にしない。

追加される中核構造は、明示ActorRef、ActorQualifiedRead、イベントの自然文見出しとfilter、文内Sequence/CST、方向付き移動、継続状態ルール、名前付き呼出し引数、数量注釈、条件の文脈別活用、通知群の参照、編集途中のHoleである。新しい構造は必ずコード/ブロックの両方へ対応する。最小数153へ合わせるために複数能力を不透明な一ブロックへ畳み込まない。

高度な組込みは正式な数学名を保持できる。平方根や三角関数を無理に幼児語に変えず、読み、入力例、結果、数/式の穴を示す。全26組込み、22状態値、5引数付きセンサー、16演算、5スコープ、全イベント/保存/編集/素材/上限は対応表から落とさない。

## 9 二つの編集表示

意味編集の入口は共通のEditorTransactionとする。文の値変更、対象変更、見出し変更、ブロック移動、引数並べ替え、範囲選択、名前変更は、同じ意味モデルへ一度だけ反映する。

原文を保持できる最小範囲を書き換える。単純な値変更で文節順や助詞やコメントを全て再生成しない。構造変更で広い範囲の生成が必要な場合は、scopeと接続を再生成する最小の文/囲いに限定する。生成文は必ず共通パーサーへ戻し、同じ意味ASTになることを確認する。

1行に複数節があるため、sourceSpanは行だけでなく節の開始/終了、nodeId、actorRef、親suiteIdを持つ。エラーの強調、実行位置、ブロック選択、注釈の所属、戻す/やり直すは節単位で対応させる。句点を増減しただけでブロックの同一性を失わない。

入力途中はDraftValue/DraftStatementに保持し、有効な作品を上書きしない。ブロックの空の囲い/穴はHoleであり、NoOperationやtrueとは違う。確定・取消のある未完状態として同じように扱う。実行時にHoleを無視して作品完成と見せない。

no-editの表示切替は文字列同一、意味同一、dirty同一、履歴同一を保証する。編集を伴う往復では、明示的に変えたところ以外の意味・名前・素材ID・所属・注釈を保つ。先頭から再パースした場合でも対応するnodeIdを回復し、対象別の選択/スクロールを保つ。

## 10 ブロックの見せ方

各ブロックには、読み上げられる文と、その中の編集できる文節を置く。カテゴリの抽象ラベルをブロック本体へ転用しない。数欄の隣に助数詞、対象の隣に助詞が見える。フォントの実測で幅を決め、長い名前も省略だけで参照先を失わない。

条件の穴は、条件句を入れると接続形まで自然に変わる。これが値を文字列へ変換する操作ではないことをモデルで分離する。手順の引数は「高さを［30］として」のように何の値かを読める。関数の結果は命令の接続形を持たず、値の穴へ入る形にする。

範囲を持つブロックは開閉の同じ線で囲み、中にいくつの命令が入るかを選択前に示す。対象の異なる位置へ移したときは、対象を維持するか、移動先の対象にするかが必要なら確認する。見た目の並べ替えで暗黙に誰の動きかを変えない。

候補検索は検索語/読み/意図タグ/利用者定義名のインデックス。候補文型の閉じた受理とは別。検索から追加する場合、意図に足りない対象/量/時間は可視の候補値か空欄にし、見えない推測はしない。新規の単純な見える命令は10歩、15度、100％、1秒、「こんにちは」を採用するが、囲いの条件や目的地が未決定ならtrue/0でごまかさない。

操作コストの評価は、意図を探す→文を置く→値を直す→動かす→間違いを戻すまで行う。単にScratchよりボタンが少ないことを目標にしない。未実測の相対優位を報告しない。

## 11 永続化と安全

新しい文型・対象・イベント・式を安全に保存できる一つの現行スキーマを定める。内部の形式識別子で完全に検証してから現在の作品へ置き換える。文字と名前のエスケープ、参照先の実在、重複ID、深さ・量・素材を検査する。読み込めなかった入力は現在の作品を変更しない。

autosaveは有効な記録を検証後に復元する。未完の作文は下書きとして別状態で保存し、最後の有効な本文へ黙って置き換えない。素材は所有するID参照を保ち、名前の一致だけで別の画像/音へ差し替えない。playerは編集アプリと同じ意味IR/実行エンジンを使い、別の簡易パーサーを同梱しない。

ネットワークを必要にしない。音声MP3/WAV PCM/M4A AAC-LC/FLAC/Ogg Opus、PNG/JPEG/WebP、画像再エンコード、素材埋込み、画像の編集時複製、お絵かき、単体HTMLを書き出す能力を保持する。CSP、HTMLエスケープ、悪意のある名前・文字・素材の検査を弱めない。

## 12 実装を分ける順序

1. 文型レジストリ・原文保持・独立意図コーパスの対応を作る。日本語として不自然な生成例を先に修正する
2. 字句/文節/条件活用/名詞句/単位を実装し、正例と反例のAST/保留状態を固定する
3. 明示対象・イベント見出し・同期実行・継続状態の意味を実装し、模擬時計で固定トレースを確認する
4. 値・リスト・手順/関数・名前付き引数・スコープ・全高度能力を意味モデルへ対応させる
5. 共通モデル上のブロック、作文支援、検索、編集回復、画面を作る
6. 保存/player/全素材/上限を照合し、独立した最終実操作QAを行う
7. 失敗を直し、影響試験と全体ゲートを最終headで再実行する。専用remoteブランチのdraft PRで止める

既知のMap監視の例外、切替ボタン高さ、数値入力の不一致は、文法変更に依存しない範囲で先に直せる。言語・対象・型の変更と合流したあとに、最終の意味契約で再検証する。

## 13 既知の不具合を仕様から追う

| 観測された問題 | 修正の要点 | 必須の再確認 |
|---|---|---|
| UIで作った引数なし手順の実行後にR411。監視経路がMapへ.mapを呼ぶ | Map/配列のモデルを明示し、実行と監視・エラー表示の双方を修正 | UIで作成/保存/検索/挿入/実行/監視を開いた状態。動いた後の例外も不合格 |
| 新規大きさ0％がR412 | 新規の既定100％、許容1〜1000％を入力で示す | 0、1、100、1000、1001、式の動的値。既存値を無断変更しない |
| コードの全角数がブロックで拒否 | 共通の数字トークン処理。文字・名前内部は保護 | 全半角、負数、－0、小数、IME、貼付け、取消 |
| 保存した手順名で検索しても置けない | 利用者定義レジストリを検索へ反映 | 保存/名前変更/取消/削除、主本文と手順本文双方、挿入後の実行 |
| 1366×768でコード/ブロック切替ボタン自体が約240px高 | flex/gridの伸長と高さ制約を修正。本文と切替を分離 | 同サイズと1280×720/1024×768/200％で実寸・文字の見切れ・本文到達 |

これらは親タスクから共有された実操作所見を含む。ここで独立に再実行したという意味ではない。PRでは再現経路と最終候補の実測証拠を付ける。

## 14 検証と証拠

固定基準は、基準版の全能力の意味、独立CI-01〜CI-20の意図/反例、新しい追加文型の契約である。既存試験を新しい構文へ書き換える際は、語形/ASTの差分と、意味期待値の差分を別にレビューする。数値、対象、順序、短絡、待ち、上限を候補実測に合わせて改変しない。正式に追加/変更した表層意味には、その理由と新旧能力の対応を残す。

検査は次の層を分ける。

- STATIC：文型集合、能力/スキーマ対応、生成例の文法閉包、資料整合、安全性
- NODE：字句/解析/意味検査/往復/模擬時計/乱数固定のトレースと境界
- BROWSER：pointer/keyboard/IME/focus/drag/layout/undo/storage/audio/download/player
- JAPANESE：生成文と受理文の主述・格・係り受け・接続・時制/相を独立レビュー
- FUTURE STUDY：実際の児童とScratchの同条件比較。今回の完成ゲートに混ぜない

ブラウザーの証拠は最終コミット、製品hash、環境、viewport、操作、表示/状態、スクリーンショットを含む。未実施・環境で止まったものをPASSにしない。既存の監査本数や上限を減らして通過しない。文型の大改訂で試験IDが変わる場合は、全旧期待値から新試験への対応が必要。

最終報告には、何が実際に動いたか、どこが未確認か、PRのhead、mainが更新されていないことを記す。文書を書いた段階で「学年に最適」「Scratchより簡単」と言わない。
