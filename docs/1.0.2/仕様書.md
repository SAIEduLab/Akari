## 1 作文の基本単位

### 1.1 言葉の役割

命令の文を、動かす対象、変更するもの、方向・位置、量、時間、動作、条件、範囲へ分けて読む。実装が探すのは助詞・単位・述語の対応であり、単語を近い命令へ推測置換することではない。

以下の三文は同じ結果になる。

```text
ねこは右へ10歩動く。
ねこは10歩右へ動く。
ねこを右へ10歩動かす。
```

一方、次の文は異なる。

```text
ねこは前へ10歩進む。          ※ ねこの現在の向きに進む
ねこは右へ10歩動く。          ※ 画面の右へ。向きは変えない
ねこは右を向いて、10歩進む。  ※ 向きを右へ変えてから進む
ねこは右に10度回る。          ※ 今の向きから右回りに回転する
```

一歩は画面上の1ピクセル。座標は左上が横0・縦0、右と下が正。0度は右、90度は下。向きの変更と移動は別の動作である。画面の表示倍率は実際の歩数・座標を変えない。

### 1.2 文節の順序

役割が明示された修飾句は、次の閉じた組合せに限って入れ替えられる。述語は末尾、対象の明示句は文または節の先頭に置く。文節の中は勝手に並べ替えない。

| 文型 | 必須役割 | 受け入れる順序の例 | 受け入れない例 |
|---|---|---|---|
| 移動 | 量＋歩、任意の方向 | 右へ10歩動く／10歩右に動く | 右へ左へ10歩動く、10動く |
| 回転 | 左右、角度＋度 | 右に15度回る／15度右に回る | 右へ15歩回る |
| 位置 | 横X、縦Y、位置への動詞 | 横100、縦50の位置へ行く／縦50、横100の位置に行く | 横100、横50へ行く |
| 時間をかけた移動 | 時間＋秒で/秒かけて、位置または方向＋距離 | 1秒で横100、縦50へすべる／横100、縦50の位置へ1秒かけて動く／2秒かけて画面の右へ40歩動かす | 1秒後にすべるを同じ文型へ解釈する |
| 代入 | 変更先＋を、値＋に、する/変える | 点数を10にする／点数を10に変える | 点数を10増やすを代入扱いする |
| 加減 | 変更先、増減量、足す/引く/増やす/減らす | 点数に1を足す／1を点数に足す／点数を1増やす | 点数を10に増やすを差分10扱いする |
| リスト挿入 | リスト＋の、番号＋番目に、値＋を | 持ち物の2番目に「かさ」を入れる／「かさ」を持ち物の2番目に入れる | 2番目を…にするを挿入扱いする |
| 発言 | 引用＋と、または値の名詞句＋を、言う/話す | ねこは「やった」と言う／点数の値を言う／ねこに「やった」と言わせる | 点数と言うを無条件に数値読みへ変える |

「に／へ」は移動の到達方向・位置で同じ意味を持つ列だけに許す。データの「に」「を」、時間の「で」「後に」「間」を一括で同義にしない。全文型は付録Aと本章の規則の直積だけで閉じる。新たな受理文型の追加には例・反例・役割AST・ブロック・トレースの五点を追加する。

### 1.2a 単位と助数詞を落とさない

「点数が10点以上なら」「点数を1点増やす」「1秒に20歩」「右に90度」「4回」「2番目」は、数だけのコードより自然な作文である。数を拾って後ろの名詞を全部捨てるのではなく、次の役割を持つ数量句として読む。

| 数量句 | 使う役割 | 正規化後の意味 |
|---|---|---|
| E歩 | 距離 | ピクセル数。方向は別の役割 |
| E度 | 角度 | 度。ラジアンへ黙って変えない |
| E秒、E秒間 | 待機時間・音の長さ | 秒。『後に』『かけて』は動詞との関係で区別 |
| E回 | くり返し回数 | 0以上の整数 |
| E番目 | リストの位置 | 1から数える番号 |
| E点、E個 | データの数え方 | 数の値と表示単位を保持。文字列ではない |
| E％ | 大きさ・音量 | 各命令の有効範囲で百分率 |
| EHz | 音の周波数 | 周波数 |
| T秒にD歩の速さで | 継続移動の速さ | D/T歩毎秒。Tは正、Dは0以上 |

点・個などのデータ単位は、明示した数値データの単位として管理する。『点数を0点にする』のような数量付き代入から単位を定める操作は、数値と単位が同時に見える一つの編集にする。単位未指定の既存データへ勝手な名前推測は行わず、数量を入れるときに「この数は点として数える」を表示して確定する。単位のない数値式・全高度演算を禁止しない。

単位を持つことが分かる値どうしの比較・加減は同じ単位であることを確認する。『点数（点）が10秒以上』を受理しない。単位が未指定なら名前だけで点と推測せず、役割を確認する。秒と点を変換する規則や、任意の後置名詞を単位扱いする規則はない。数値を単位なしで取り出して高度な式に使う経路も持ち、数学能力を減らさない。単位欄を変えても数値そのものを換算しない。

単位・助数詞はブロックでも数欄の外の見える文として残り、何を入力する場所かを示す。生成・保存・往復で消さない。比較の活用表のYには数量句も入るので、『10点以上なら』は正式な受理形である。

### 1.2b 単位を持つ値の受け渡し

単位の本体は数値に付くメタデータである。数値は `大きさ＋単位なし/登録単位` として持ち、単位付きも「数」の一種とする。変数の宣言には、任意の「このデータは点で数える」などの単位制約を別に持てる。名称そのものに単位の意味を持たせない。リスト項目・引数・返り値に単位を付け替えることはない。

単位だけを外して数式へ使う正式な形を `点数の数だけ`、任意の式では `（式）の数だけ` とする。ブロックも `［値］の数だけ` という数の式。大きさをそのまま保ち、単位だけを外した新しい値を返す。元のデータは変更しない。文字を数に変える既存の `数（文字）` とは区別する。これにより、すべての高度な数式へ単位なしの有限数を渡せる。

| 場所・操作 | 単位の扱い | 不一致と単位なし |
|---|---|---|
| 変数への代入 | 値の単位を保存。宣言側に単位制約があれば一致を確認 | 制約なしなら全従来の数/文字/条件の値を保存可能。制約ありに別単位・非数値を入れない |
| リスト・項目読取り・snapshot | 各項目の数と単位を一緒にコピー。異なる型/単位の項目が混在できる | 全リストを一つの単位へ統一しない。項目数/番号はそれぞれの役割を持つ |
| 手順/答えへの引数と返り値 | 値の単位をコピーして保つ。局所データにも保持 | 受け取り側の動作や演算に必要な単位を検査。引数名から推測しない |
| 足す/引く・大小/数の等値比較 | 単位が同じ数はその大きさで演算/比較。加減の結果は同じ単位 | 点と秒など明示単位の不一致は診断。片方が単位なしなら、この役割で他方と同じ単位として使うことを表示し、数値は換算しない |
| 数値データを増やす/減らす | 変更先の単位を結果へ保つ | 単位なしの増分は変更先の単位で数える。別単位の増分は拒否 |
| 掛ける | 単位付き×単位なし、または逆は、単位を保つ | 単位付き×単位付きの複合単位は作らない。「の数だけ」で数値の計算へ進める |
| 割る | 単位付き÷単位なしは単位を保つ。同じ単位どうしは単位なしの比 | 異なる単位や単位なし÷単位付きの複合単位は作らず、数だけを使う形を示す |
| 符号・絶対値・四捨五入・切上げ/切捨て | 単位を保つ | 基準の有限数/丸め規則は変えない |
| 最小/最大・乱数・余り | 比較可能な共通単位を保つ | 明示単位が違えば拒否。単位なしのみなら基準どおり |
| 累乗・平方根・対数・指数等 | 単位なしの数を対象にする | 単位付きには「の数だけ」を提示。演算自体を削除しない |
| 三角関数 | 度、または単位なしを基準の度として使う。結果は単位なし | 別単位は拒否。逆三角関数の数値は度として使える角度の値を返す |
| 文字への変換・発言・連結 | 単位付き数は「10点」のように単位を含めた文字化 | 数だけを出したければ「の数だけ」。文字「点」を勝手に削って重複を直さない |
| リストの一致検索 | 数と単位が同じ項目を同じ値として扱う | 単位なしの1、1点、1秒は別項目。混在リストの検索で他単位を換算しない |
| 保存/復元/player | 数値と単位、宣言制約を検証して保持 | 未知の単位や壊れた値を落として読まない |

数・文字・条件の値どうしの通常の等値規則は基準を保ち、全体を文字化して比較しない。数量のために任意の文字やBooleanを数へ変換しない。単位を伴う物理量の状態読み取りは、横/縦位置・距離=歩、方向=度、タイマー=秒、大きさ/音量=％という固定の役割を持つ。数だけを求める場合にも同じ値へ到達できる。

未指定データの単位を定める確認は、編集時のtransactionで行う。構文だけから型を確定できない未完の文を実行しながら質問することはしない。確定前は原文と直前の有効モデルを保持し、確定時にソース・単位制約・履歴を一度に更新する。読込み/実行時に動的な値だけで判明した不一致は、該当する式を示すruntime診断として停止する。実行中に単位を自動設定・変更しない。

例：`「いまは」と（点数の数だけ）と「点だよ」をつなげて言う。` は、点数が3点のとき「いまは3点だよ」。`点数の値を言う。` は「3点」。数字と単位を別々に使う違いを、文とブロックの両方で表せる。

### 1.3 主語の省略と明示対象

できごとの見出しは、最初に動く対象を決める。本文はその対象を省略して書ける。文の中で新しい対象を明示したら、その字下げ範囲の以後の命令では、その対象を省略できる。字下げした枝・くり返しから外へ戻ると、外側で決まっていた対象へ戻る。空行・コメント・画面の選択はこの範囲を変えない。

これは実行時の「最後に動いたもの」を調べる仕組みではない。構文解析時に、各命令の対象を字下げ範囲ごとに確定する。実行しなかった枝、別の実行、別のキャラクターの動きで対象が変わらない。

```text
作品を動かしたとき、ねこは、
  右へ10歩動く。
  いぬに「着いたよ」と言わせる。
  左へ5歩動く。          ※ いぬ。直前の明示対象をこの範囲で引き継ぐ
  もし点数が10以上なら、
    ねこは前へ3歩進む。
  前へ2歩進む。          ※ いぬ。枝の中の対象指定は外へ漏れない
```

対象の継承を変えるのは、動作文で明示した動作主・被動作対象だけ。条件の主語、接触相手、距離の相手、データの持ち主、素材名、知らせの受け手を読んでも変えない。

```text
作品を動かしたとき、ねこは、
  もしいぬがねこにふれていれば、
    「さわった」と言う。  ※ ねこが言う
  前へ10歩進む。          ※ ねこが進む
```

`いぬの点数の値を言う。` でも、点数の持ち主はいぬ、言う対象はその範囲の対象である。条件や状態の主語付き読取りは、動作文の主語変更と違う役割として保持する。

対象を引き継いだ全ブロックとコードの各実行節には、小さな名前印で実際の対象を常時確認できる。印は文の代わりに意味を隠す場所ではない。名前印を選ぶと、「いぬは」など対象を明示した文へ、意味を変えずに書き直せる。子どもにこの省略規則の暗記を求める入口にはしない。初めて複数対象を置くときは、対象付きの文をそのまま入れる。

明示対象は、その文の動き・見た目・自分のデータ・状態読み取り・手順呼出しに適用する。別の対象を指定しても、新しいできごとや並列の実行は起動しない。前の命令の終了・待機規則を保ったまま同じ実行で次へ進む。対象の違う手順を呼んでも、その手順を最後まで終えるまで呼出し元の続きを進めない。

名前で指定した部品は元の部品を指す。分身のできごとで省略された対象は、その分身である。分身から明示的に「ねこは」と書けば元のねこを指す。「自分」はその節で確定した実行対象を指す。共有手順の入口の自分は呼び出した対象であり、手順をしまってある場所を意味しない。

動作対象のある文型だけで主語/対象を抽出する。「点数を10にする」の「点数」を部品名扱いしない。「ねこに『こんにちは』と言わせる」の「に」は発言させる対象、「持ち物の最後に」の「に」は置き場所である。文型が同定される前に先頭の助詞だけを削らない。

### 1.3a 話す内容と値の格を分ける

引用した台詞は「こんにちは」と言う。データや答えは、点数の値を言う、答えを言う、（式）の値を言う、（…で求めた答え）を言う、と書く。「と」を名詞句へ一律に付けない。出力は吹き出し/出力欄の文字であり、音声合成ではない。引用文字列と名前から読んだ値をブロックでも見分けられるようにする。

### 1.4 句点と続く文

句点「。」は入力時に省略できる。生成では通常付ける。句点で終わる複数の文を同じ行に書ける。改行は文末または認めた見出しの後に置く。長い文の途中での表示上の折返しは、ソースの改行にしない。

順序を表す「そのあと、」「それから、」「次に、」は命令文の先頭に置ける。処理順は本文順であり、これらがあってもなくても同じ。「同時に」はこれらの同義語ではない。

## 2 いつ始まるかを書く

できごとの見出しは、コードでもブロックでも直接編集できる。本文から離れたドロップダウンだけに閉じ込めない。見出しを変えたときは、実行対象・きっかけ・絞り込みをひとまとまりで変更する。本文・履歴・未確定入力を失わない。

| きっかけ | 自然な見出しの標準形 | 正確な意味 |
|---|---|---|
| start | 作品を動かしたとき、ねこは、 | 「動かす」で起動する。既に動いている間に常時繰り返す意味ではない |
| click | ねこがクリックされたとき、 | 対象へのクリックごとに始まる。ねこをクリックしたとき、も受理 |
| keyDown | キーが押されたとき、ねこは、 | どのキーでも一度の押下ごと。OSの押し続けによる自動反復を新しい押下にしない |
| keyDown＋filter | 「空白」キーを押すたびに、ねこは、 | 指定したキーの押下で開始。押している状態を常時調べる見出しではない |
| message | 知らせを受け取ったとき、ねこは、 | すべての知らせ。受け取った知らせを本文で使える |
| message＋filter | 「出発」という知らせを受け取ったとき、ねこは、 | 一致する知らせで始まる |
| backdropChanged | 背景が変わったとき、ねこは、 | 前の背景名・新しい背景名をこの実行から読める |
| valueChanged | 入力欄1の中身が変わったとき、 | 入力欄の変更時。前の値・新しい値を読める |
| cloneStart | ねこの分身が作られたとき、 | 新しくできた当人が動く。元のねこや既存の分身すべてを再起動しない |

「始まったとき／開始したとき」「クリックするたびに／クリックされたとき」「押すたびに／押されたとき」は、それぞれ表の該当イベント位置で受理する。「押されていれば」は条件の位置で扱う。「小さくなったら」のような状態変化の見張りは、普通のifへ読み替えない。対応するイベントがないときは、現在の値を調べたいか、変化する瞬間を待ちたいかを確かめる。

通常のできごとは、前回の本文が終わる前にもう一度起きても、各回が別の実行として開始する。無断で前回を消したり一回を捨てたりしない。手順の重なりが生じる場合は実行中の数を示す。状態の継続ルールの再入とは別の契約である。

同じ対象・種類の見出しも複数作れる。それぞれ独立した本文IDを持ち、一致したすべての本文を登録順に開始する。既存本文を上書きして数を合わせない。上限は本文全体で1000個以上を維持する。基準版の全32の対象種別/イベント組合せはすべて作れる。

見出しの後に短い本文を同じ行に書くこともできる。ブロックへ移ると見出しと本文の区別が見える。見出しをただのコメントへ変換して実行条件を失わない。

### 2.1 押しているあいだ動き続ける

代表的な継続動作は、子どもにイベント・while・刻み幅・待ち時間へ分解させず、一つの文で書けるようにする。

```text
「右」キーを押しているあいだ、ねこは画面の右へ1秒に20歩の速さで動き続ける。
```

文型は `状態のあいだ、対象は方向へT秒にD歩の速さで動き続ける`。自他の別形は `状態のあいだ、対象を方向へT秒にD歩の速さで動かし続ける`。方向句と速さ句は入れ替えられる。`間は`、`あいだは`、`押している`と`押されている`を、この継続キー状態の文型で受理する。状態は第4節の条件、方向は前/後ろ/画面の上下左右、速さは明示数量に限定する。条件と移動の対象が確定した、作品全体の継続ルールを一つ登録する。

『右へ動かし続ける。1秒に20歩の速さで動かす。』という独立コーパスの二文は、直前の未完の継続動作に速さを加える一つの構造編集候補として扱う。結合対象の二文を同時に示し、確定してから実行する。速さのないまま10歩/0.1秒などを補わない。ブロックから新規作成する場合は、見える既定の速さ20歩/秒が最初から文に入る。

実行の契約：

- 作品が動いている間、条件を監視する。開始時からキーが押されていれば動き始める
- 条件が成立している期間だけ、経過した論理時間に比例して移動する。表示更新回数に移動量を依存させない
- 一つのルールと対象の組につき有効な制御は一つ。OSのキー反復や素早い離し直しで同じ制御を重ねない
- 離した時刻までの移動を確定し、その後の移動を止める。再び押せば新しい成立期間として再開する。前回の待機タスクを残さない
- 速さの式は各成立期間の入口で一度だけ評価する。前/後ろ方向は各時間区間の現在の向きを用いる。画面方向は向きを変えない
- 異なるルールの同時移動は、それぞれの変位の和とする。右20歩/秒と左20歩/秒なら相殺する。最後に登録された側で黙って上書きしない
- 他の一回移動・回転・待ちと同時に使える。実行ログは適用順とルールIDを残す。『ほかの実行を止める』で止められた制御は、条件が一度不成立になるまで自動再開しない
- 作品全体の停止・一時停止・再開は論理時計に従う。停止で制御を破棄し、次の実行は作品の初期状態から始める

この継続ルールを、単なるwhileの別名へ戻してはならない。通常のwhileは到達したときから本文を反復する能力として別に残す。作品全体のルールは元の登録部品を対象とし、分身へ無断で複製しない。分身自身の反復能力は既存のできごと＋反復で保持する。

受入 `CONTINUOUS-STATE`：0.5秒で10歩、1秒で20歩という模擬時計の厳密トレース、実時計では入力時刻/表示時刻を記録した許容誤差、開始時押下、押下なし、解放、50ms間隔の離し直し、キー反復、二方向同時、他の動きとの競合、一時停止、全体停止、target削除を確認。異なる描画頻度でも同じ入力時刻列なら同じ位置列となる。

## 3 順序とまとまり

### 3.1 動詞をつなぐ

次の文は三つの独立した命令をこの順で実行する。

```text
ねこは姿をかくして、1秒待って、姿を見せる。
```

命令をつなぐ活用は、文型ごとの表で持つ。開始時に必須の活用対は、進む/進んで、動く/動いて、動かす/動かして、回る/回って、向く/向いて、行く/行って、すべる/すべって、する/して、変える/変えて、言う/言って、話す/話して、言わせる/言わせて、待つ/待って、かくす/かくして、見せる/見せて、入れる/入れて、足す/足して、引く/引いて、消す/消して、知らせる/知らせて、行う/行って、鳴らし始める/鳴らし始めて、鳴らす/鳴らして。辞書の文字列末尾だけを書き換えて新しい動詞を発明しない。

単位を持つ式の中、名前、文字列、コメントは接続で分割しない。「待ってから」は待機完了後、「知らせてから」は知らせを発した後であり、受け手の終了を追加で待つ意味にはしない。非同期の開始命令は「始める」を文に含める。音の扱いは第8節による。

「もしCなら、右を向いて、10歩進む」では二命令ともifの中にある。句読点の数から適当に外へ出さない。1命令ずつ実行するときは、同じ行の中の各節を個別に示す。

### 3.2 字下げ

字下げされた本文は直前の見出しに属する。標準生成は半角空白2個で1段。入力は各範囲でそろった半角空白の段階を受け入れる。タブ・全角空白の字下げは、範囲を示して置換候補を出し、確認前に勝手に整えない。空行・コメントは範囲を変えない。

コードでは囲いを薄い線で、ブロックでは囲い本体で示す。開始と終わりを選ぶと、対象となる文だけを同時に強調する。「ここまで」は通常文法に加えない。範囲を画面と字下げで決め、終端語が抜けたため違う構造になる問題を増やさない。

空の囲いは下書きとして置ける。空の実行内容を勝手に「何もしない」という命令に変えない。実行・保存可能な確定作品では、空の囲いをエラーとして直すか、利用者が明示的に「何もしない」を選ぶ。トップレベルの空本文は有効。作成直後に必須式を真や0で埋めて意図を偽装することも禁止する。

## 4 条件を自然な述語で書く

### 4.1 単純な条件と活用

条件はその文に到達した時点の状態を調べる。ifは一度、あいだ/までは各回の本文の前に調べる。未来の変化を監視し続けるifではない。

| 条件の述語 | もしに続く形 | 否定の条件形 | あいだ | まで |
|---|---|---|---|---|
| XがY以上 | XがY以上なら | XがY以上でなければ | XがY以上のあいだ | XがY以上になるまで |
| XがY以下 | XがY以下なら | XがY以下でなければ | XがY以下のあいだ | XがY以下になるまで |
| XがYより小さい | XがYより小さければ | XがYより小さくなければ | XがYより小さいあいだ | XがYより小さくなるまで |
| XがYより大きい | XがYより大きければ | XがYより大きくなければ | XがYより大きいあいだ | XがYより大きくなるまで |
| XがYと同じ | XがYと同じなら | XがYと同じでなければ | XがYと同じであるあいだ | XがYと同じになるまで |
| XがYと違う | XがYと違えば | XがYと違わなければ | XがYと違うあいだ | XがYと違う状態になるまで |
| Kキーが押されている | Kキーが押されていれば | Kキーが押されていなければ | Kキーが押されているあいだ | Kキーが押されるまで |
| Kキーが押されていない | Kキーが押されていなければ | Kキーが押されていれば | Kキーが押されていないあいだ | Kキーが押されなくなるまで |
| 対象にふれている | 対象にふれていれば | 対象にふれていなければ | 対象にふれているあいだ | 対象にふれるまで |
| 対象にふれていない | 対象にふれていなければ | 対象にふれていれば | 対象にふれていないあいだ | 対象にふれなくなるまで |
| マウスが押されている | マウスが押されていれば | マウスが押されていなければ | マウスが押されているあいだ | マウスが押されるまで |
| 分身である | 分身なら | 分身でなければ | 分身であるあいだ | 分身になるまで |
| LにEが入っている | LにEが入っていれば | LにEが入っていなければ | LにEが入っているあいだ | LにEが入るまで |

表のX/Y/K/L/Eは値を示す文法変数で、利用者が入力する文字ではない。「もし」は省略しても条件見出しとして一意な形なら受理する。「ならば」「であれば」、い形容詞の「小さいなら」、状態の「押されているなら」も正しい別形として受理する。正しいが採用しない別の言い方を「日本語の誤り」と表示しない。

否定はNOTという意味を保つ。値の型が不正であることを「あてはまらない」に変えない。「小さいではない」「押されているではない」を生成しない。否定を不等号へ機械置換して評価順や診断を変える必要はない。

表の「まで」は、最初からその状態なら一度も本文を行わない、または直ちに待機を終える。次の状態変化を一回待つ意味ではない。「一度はなしてから、もう一度押すまで待ちたい」なら、押されなくなるまで待つ文と押されるまで待つ文を順に書く。文が「変わる瞬間」を要求しているのに現在状態だけで成功させない。

### 4.2 二つの条件

単純な述語どうしは、閉じた接続活用でつなげる。

```text
もし点数が10以上で、「空白」キーが押されていれば、
  ねこは「できた」と言う。
もし点数が10以上か、「空白」キーが押されていれば、
  ねこは「できた」と言う。
```

前者は両方、後者は少なくとも一方。後者は両方があてはまっても一度だけ本文を行う。ANDは左があてはまらなければ右を評価せず、ORは左があてはまれば右を評価しない。名前を読む順や乱数の回数もこの順序に従う。

接続形は、以上/以下/同じ→で、違う→違っていて、小さい/大きい→小さくて/大きくて、押されている→押されていて、ふれている→ふれていて、入っている→入っていて、である→で。否定形は各文型に登録した「ではなくて／小さくなくて／押されていなくて」などを使う。

3個以上、入れ子、ANDとORの混在、全体の否定は、括弧でまとまりを明示できる。

```text
もし条件（（点数が10以上）かつ（残り時間が0より大きい））が成り立つなら、
  「続けられる」と言う。
もし条件（（点数が10以上）または（「空白」キーが押されている））が成り立たないなら、
  「まだだよ」と言う。
```

この汎用形は任意の条件式を保持するための形であり、初歩の単純条件に強制しない。「AかBでなければ」の否定範囲や、混ざった「AでBかC」の範囲を推測しない。二つの囲い方と、それぞれの意味を示して選んでもらう。元の文は残す。

### 4.3 条件に当てはまらない側

```text
もし点数が10以上なら、
  「やった」と言う。
そうでなければ、
  「あと少し」と言う。
```

「そう」は直前の同じ字下げのifの条件全体を指す。囲いの見出しを選ぶと、対応する条件と二つの枝が同時に示される。別の実行文を挟んだelse、孤立・二重elseは拒否する。空行・コメントを挟むことはできる。「そうでなければ」を初心者向けに常に「いいえなら」へ言い換えない。

## 5 くり返すものと待つもの

| 文型 | 標準形 | 実行契約 |
|---|---|---|
| 回数 | 3回くり返す。＋本文 | 入口で回数を一度評価。0回なら本文なし |
| 範囲が明示された一文 | 10歩進んで、1秒待つことを3回くり返す。 | 「ことを」の前の命令列全体を反復。ブロックで囲いに展開できる |
| あいだ | 点数が10より小さいあいだ、くり返す。＋本文 | 各回の前に判定。初めから不成立なら0回 |
| まで | 「空白」キーが押されるまで、くり返す。＋本文 | 各回の前に成立を調べ、成立なら終了 |
| ずっと | ずっとくり返す。＋本文 | 止めるまで反復。ほかの実行を独占しない |
| リストごと | 持ち物の中身を先頭から一つずつ見て、次のことを行う。＋本文 | 開始時のコピーを順に使う。元から取り除かない。空なら0回 |
| 時間待ち | 1秒待つ。 | この実行だけ待つ。他の実行は進む |
| 条件待ち | 「空白」キーが押されるまで待つ。 | この実行だけ待つ。既に成立なら直ちに続く |
| 反復終了 | いまのくり返しを終える。 | 最も内側の反復を終了。呼出し境界を越えない |
| 次の回 | この回の残りをとばして、次の回へ進む。 | 最も内側の反復の残りを行わず次の判定へ |

リスト反復の本文では「今見ているもの」がその回の値を指す。任意の項目名を使う場合は、本文先頭に「この中では、今見ているものを【品物】と呼ぶ。」を置く。これは反復の項目名の宣言であり、実行して値を変える文ではない。入れ子では最も内側の今の項目を指し、名前を付けた外側の項目も読める。項目は読取り専用で、元のリストを取り除かない。

反復本文がいくつの命令からなるかを、句点・読点の数で推測しない。「3回進んで、待つ」は確認が必要な文。「進むことを3回くり返して、待つ」は前進だけ3回。「進んで、待つことを3回くり返す」は両方3回である。反復を含む一行は、文型がこの二つに分かれることを構文木と予測表示で示す。より深い一行の入れ子は字下げへ案内する。

## 6 値とデータ

### 6.1 値の種類と表示

数・文字・条件の答え・それらを並べたリストを保持する。型を推測して黙って変換しない。リストの入れ子は基準と同じく扱わない。文字の数はUnicodeコードポイントで数え、絵文字・結合文字の見た目との違いは詳しい説明で示す。

| 種類 | コードの例 | ブロック・初期値・調査画面 |
|---|---|---|
| 数 | 10、－10、0.5、（1＋2）×3 | 符号付きの数をそのまま入力。任意の式にも置換できる |
| 文字 | 「こんにちは」 | かぎ括弧を見せる。空文字も本当の値 |
| 条件の答え | 条件の答え（あてはまる）／条件の答え（あてはまらない） | 型名を「条件の答え」、選択肢を「あてはまる／あてはまらない」。裸の「偽」だけを見せない |
| リスト | ［1、2、3］ | 並び順が見え、追加・削除・移動・式の入れ子を編集できる |

条件の答えの二つは内部のBoolean true/false。0、空文字、未入力、文字列「いいえ」とは別である。データとして必要なときだけ名詞句「条件の答え（…）」を使う。単純なifには付けない。正式用語の真・偽は「くわしく」の説明で併記できるが、通常UIの生成語と初心者の出力を裸の真/偽にしない。はい/いいえを質問のない場所の中心語にはしない。

値の文字化はtrue→「あてはまる」、false→「あてはまらない」。Say、連結、文字変換、監視、エラーの値、単体HTMLで統一する。文字列が同じ見た目の場合でも、調査画面は型と文字のかぎ括弧を表示して区別する。

```text
当たりを（点数が10以上）の答えにする。
当たりを条件の答え（あてはまらない）にする。
もし条件（当たり）が成り立つなら、
  「当たり」と言う。
```

上の「の答え」は条件式の結果を名詞として置く形であり、もう一度計算する指示ではない。式は一度だけ評価する。

### 6.2 データの文

- 点数を10にする：今の値を10に置き換える
- 点数を1増やす／点数に1を足す：今の値に1を足す
- 点数を1減らす／点数から1を引く：今の値から1を引く
- 持ち物の最後に「かさ」を入れる：個数が1増える
- 持ち物の2番目に「かさ」を入れる／2番目の前に入れる：元の2番目から後ろが一つずれる
- 持ち物の2番目を「かさ」に変える：個数は変わらない
- 持ち物の2番目を消す：後ろが一つずれる
- 持ち物の中身を全部消す：リストそのものの登録は残る

リストは1番目から。挿入は現在の個数＋1番目まで、読取り・置換・削除は存在する番号だけ。「持ち物に『かさ』を入れる」のように、最後へ追加か別の置き換えかを決められない一般形は、勝手に代入へ決めない。「最後に入れる」など意図の選択肢を示す。

名前を「箱」にたとえる説明だけで意味を済ませない。変更前の値と変更後の値、リストの並びの変化を確認できるようにする。変数・リスト・素材の作成や管理へ、初歩の画面からも到達できる。

### 6.3 名前と所属

名前の区切りは登録数や現在値から推測しない。普通の短い名前は裸で使える。助詞・記号・固定語と境界が衝突する名前は【名前】として、一つの名詞として扱う。候補から挿入するときは必要な区切りを自動で付ける。入力途中の自然文へ、理由なく「【】で囲んでください」だけを返さない。

所属は、作品の点数、自分の点数、この呼出しの局所データ、受け取った値、リストの今の項目を区別する。基準の名前解決順は、反復項目→局所→引数→実行対象→作品。変更先・読取りの両方に適用し、項目は読み取り専用。裸の名前を整形の都合で勝手に「作品の」へ固定しない。明示対象付きの文では「自分の」はその文の対象に属する。

## 7 手順と答えを求める定義

### 7.1 自分でまとめた手順

初めは引数なしの「ジャンプ」などを作れる。コードとブロックの両方に、名前・受け取る値・本文・この手順を使う文を一緒に示す。

標準的な呼出し：

```text
【ジャンプ】という手順を行う。
高さを30として、【ジャンプ】という手順を行う。
ねこは高さを30として、【ジャンプ】という手順を行う。
```

汎用の呼出しは引用された名称＋「という手順を行う」とする。名前が「増やす」でも「【増やす】という手順を行う」と正しく読める。「増やすする」「増やすの手順」を生成しない。作成者は任意で短い呼出し文「ジャンプする」を登録できる。この文は定義と一緒に保存した完全一致の別形であり、形態変化を勝手に推測しない。組込み文型と衝突する短形は登録時に拒否し、未登録の短形は実行せず候補を示す。正規の呼出し文はすべての定義で必ず使える。

呼出しは「高さを30、回数を2として、【ジャンプ】という手順を行う」のように、値が何かを名前で示せる。構文解析は名前付き実引数として読み、定義との対応は意味検査で確認する。引数名の重複・不足・未知の名前を拒否する。引数の式は記述順に一度ずつ評価してから、定義の名前へ対応づける。ブロックの引数順を変えたときもこの順序が見える。位置順の高度な形「（30、2）を渡して、【ジャンプ】という手順を行う」も用意し、任意の引数名と全能力を保つ。数・文字・条件の答え・リストを保つ。数だけに制限しない。リストも値をコピーして渡す。手順呼出しは同期的で、手順の待機が終わり本文が終わるまで次へ進まない。手順内部で知らせた別の実行を自動で待つわけではない。

定義見出しは名詞による見出しとして `ジャンプという手順（受け取る値：高さ）` を表示・編集する。本文は例えば次になる。

```text
縦位置を縦位置－高さにする。
0.2秒待つ。
縦位置を縦位置＋高さにする。
```

定義は作品内で共有できる。定義の保管場所と、呼出し時に動く対象を取り違えない。名前を変える下書き、本文を変える下書き、登録済みの定義を別状態として保持し、保存操作で定義全体を一度に登録する。

### 7.2 値を求める定義

表示名は「答えを求める」、詳しい説明に「関数」を併記する。数以外も返せるため、数だけの「計算」と思わせない。

```text
（数一覧を［1、2、3］として、【合計】で求めた答え）を言う。
```

定義見出しは `合計という答えの求め方（受け取る値：数一覧）`。本文例：

```text
この中だけで使う変数【合計値】を作り、最初は0にする。
数一覧の中身を先頭から一つずつ見て、次のことを行う。
  この中では、今見ているものを【数】と呼ぶ。
  合計値に【数】を足す。
合計値を答えとして返す。
```

末尾に一度だけ答えを返す。外部のデータ変更、動き、見た目、発言、質問、通知、待機、音、分身、停止、手順呼出しは使えない。引数・局所データの操作、条件、反復、ほかの答えの呼出しは使える。外部の読取り・センサー・乱数は保持するため、参照透過な関数とは約束しない。再帰、引数32個、呼出し深さ64、計算量上限を保持する。

局所変数・局所リストは定義の先頭で作る。`この中だけで使うリスト【結果】を空で作る。` は呼出しごとに新しいリスト。再帰の各回で別の値を持つ。定義を閉じたら作品のデータへ昇格することはない。

## 8 画像 音 知らせ 分身

### 8.1 目に見える動作

衣装・背景・文字・入力欄・重なり・色・大きさ・ペンをすべて維持する。背景は作品全体、衣装はその対象、線とスタンプの全消去は作品全体に作用する。対象付き文にしても背景をキャラクター固有に変更しない。

大きさの新規ブロックは100％、前進は10歩、回転は15度、発言は「こんにちは」、時間待ちは1秒から始める。既に書かれた0や空文字を都合のよい値へ書き換えない。大きさ0％は許容範囲外として入力時に具体的に示し、実行して初めてR412になる導線をなくす。

### 8.2 音を始めることと終えること

この言語では「鳴らす」を、その音の終了まで待ってから次へ進む命令と定める。日本語の「鳴らす」という語形そのものが完了を表すと説明しない。次へすぐ進ませたいときは「鳴らし始める」を用いる。音を鳴らす二つの能力はどちらも残す。

```text
音「ベル」を鳴らす。                  ※ この音の終了を待つ
音「ベル」を鳴らして、10歩進む。      ※ 終わってから進む
音「ベル」を鳴らし始めて、10歩進む。  ※ 再生を始め、進む
440Hzの音を0.2秒鳴らす。              ※ 0.2秒の終了を待つ
440Hzの音を0.2秒鳴らし始める。        ※ 始めてすぐ次へ進む
```

「終わるまで待つ」の対象は開始したその音であり、別の音や作品全体ではない。音量0〜100％、音程1段階＝半音、全音停止と待機解除、一時停止、全対応音声形式を維持する。音を開始するだけの能力を「かんたんだから」と削除しない。

### 8.3 知らせと受け手の終了

```text
みんなに「出発」と知らせる。
そのあと、ねこは10歩進む。
```

知らせは画面・全個体に届き、自分にも届く。受け手の実行は始まるが、その終了を待たずに送った側も進む。

```text
みんなに「出発」と知らせて、
  その知らせを受けて始めたことが全部終わるまで待つ。
ねこは10歩進む。
```

上は文の続き用の特殊な字下げを導入しないため、そのまま確定形にはしない。自然な確定形は次の一文、または下記の二文である。

```text
みんなに「出発」と知らせて、知らせを受けて始めたことが全部終わるまで待つ。
```

二文で書く場合：

```text
みんなに「出発」と知らせる。
その知らせを受けて始めたことが全部終わるまで待つ。
ねこは10歩進む。
```

「その知らせ」は同じ字下げ範囲で直前に送った知らせだけを指す。対象の文と待機文を線で結び、確認できる。曖昧な以前の知らせや別の実行の知らせを推測しない。待つ範囲はその送信で直接始まった全実行。その先で待たずに出した別の知らせの実行までは含めない。直接の受け手が一つもなければ直ちに続く。

### 8.3a たずねた答えを使う

```text
「名前は何ですか」とたずねて、答えを待つ。
答えを【名前】という変数に入れる。
【名前】と「さん、こんにちは」をつなげて言う。
```

最初の文は質問を表示し、回答が確定するまでこの実行を待たせるAskの完全な文型。『聞いて、答えを待つ』『たずねる』も同じ待機を持つ。『返事』はこの文型内の『答え』の別形。質問が重なった場合は順に表示し、他の実行は進める。

『答え』は質問した実行ごとの最新の確定文字列。別の実行の答えでは上書きしない。二文目は既存の変数への代入であり、以後に質問しても保存した【名前】の値は変わらない。三文目は2個以上の数・文字・条件の答えを記載順につなげて発言する文型で、元のデータを書き換えない。値をさらに使う高度な `つなぐ（値…）` も維持する。

「答える」またはIME変換確定後のEnterで回答を確定する。空欄は空文字という回答として有効で、勝手な名前を補わない。空白・引用符・かな・漢字は文字のまま保持し、コードとして解釈しない。答えの長さ上限は100000コードポイント。

質問画面の「実行を止める」は回答を作らず作品全体を停止する。Escapeも同じ停止に対応させ、IME中は奪わない。「キャンセルしたので前の答えで続ける」「キャンセルしたので空文字で続ける」は行わない。停止後は待機中の質問・後続命令を残さず、次の実行で古い回答を使わない。

受入 `ASK-ANSWER`：未回答では挨拶しない、同時質問は順番に表示、実行別回答、空文字、全空白、引用符、IME、Enter、停止、再開始、長さ境界、保存した名前と後の答えの独立を確認する。

### 8.4 分身と停止

自分の分身を作る、名前で指定した部品の分身を作る、この分身を消す能力を維持する。分身は実行中の姿と個体データをコピーし、作品データを共有する。編集時の複製とは異なり、実行終了後や作品ファイルには新しい部品として残さない。

停止は三つを区別する。`この実行を止める。` は現在の呼出しを含む実行全体、`ほかの実行をすべて止める。` は同じ対象だけでなく作品内のほかの進行中の実行、`作品全体を止める。` は新しいイベントの受付・音を含む実行全体を止める。これらを単に「動きを止める」という同じラベルにしない。各候補に、どの続きが実行されなくなるかを図ではなく実際の本文の強調で示す。

## 9 文字と名前を保護する

字句解析を構文解析より先に行う。文字列 `「…」`、名前 `【…】`、対応する括弧 `（…）`、リスト `［…］`、コメント `※…` を先に区切る。文字と名前の中の助詞・句読点・単位・活用語を外側の文法として読まない。

文字列の `「` `」` とバックスラッシュを表すエスケープを `\「` `\」` `\\` とする。ほかの未知のエスケープは自動で消さず診断する。文字の内容を改行に変える暗黙規則は導入しない。必要な改行文字の能力を追加する場合は別の値表現と往復試験を定義する。

数字・演算子・括弧の全半角対応はトークン外側だけで正規化する。文字列・名前・コメントにNFKCやかな漢字変換をかけない。`「１０歩うごく。※右へ」` は常にそのままの文字である。エラーの位置とブロックからの編集範囲は原文の位置に対応する。

かな形は単語検索だけでなく、登録した文型の述語・単位として実際に受理する。初版必須は、動く/うごく、動かす/うごかす、進む/すすむ、回る/まわる、向く/むく、待つ/まつ、言う/いう、話す/はなす、触れる/ふれる、繰り返す/くり返す/くりかえす、隠す/かくす、見せる/みせる、入れる/いれる、消す/けす、足す/たす、引く/ひく。活用形も同じ語彙レコードに登録する。全単語を一括置換しない。

## 10 ブロックの契約

1. 文型とブロックは共通の役割定義から作る。コードが「持ち物の2番目に『かさ』を入れる」なら、ブロックも同じ文として読める。「リストを挿入」のような別の抽象ラベルに戻さない
2. 穴は数だけの箱にしない。すべての式が必要な場所へ入る。数の直接入力と高度な式の切替で情報を失わない
3. 条件を反復へ入れたとき、述語は「押されている」から「あいだ」「押されるまで」へ正しくつながる。同じ条件ASTを型の異なる文字として扱わない
4. 順番をつないだ一文は各節に分けて選択・移動・1命令実行できる。元の一文へ戻すと節の順序と原文を保つ
5. 対象・期間・繰り返す範囲・条件に当てはまる側を、実行前に本文上で確かめられる。予告のために本番の状態・乱数を実行しない
6. 空の穴や囲いは編集途中の下書きとして見せる。空欄を0や真に黙って変えない
7. 検索はかな・漢字・一般的な制作意図・保存した手順名・答えの名前を含む。検索結果から直接、正しい本文へ挿入できる
8. 使用できない候補を調べると、利用できる対象・理由・移動先を示す。書きかけを削除しない
9. クリック、ドラッグ、キーボードを併設する。置ける場所を置く前に示し、領域外・Escape・ポインター中断を安全に取り消す
10. 最小の操作で原因を調べられるよう、選択した文からの1命令実行・状態の表示・待ちの可視化を維持する。本文の一部を試す場合の初期状態・副作用を明示する

### 検索と構文は分ける

「かくれたい」から「姿をかくす」が見つかることと、「かくれたい」を命令として実行することは別である。検索候補を選べば実行できる文が入る。文として書いた場合は、願望か命令かを無視して走らせない。「この文で動かすなら『姿をかくす』にできます」と候補を出す。作品の秘密の文や名前をネットワークへ送らず、オフラインで行う。

## 11 編集 回復 保存

コードとブロックは同じ意味モデル・同じ下書き・同じ履歴を編集する。見る方法を切り替えるだけでは原文、未保存表示、履歴、選択、スクロールを変えない。解析できないコードは原文のまま残し、変換できなかった箇所を偽のブロックにして成功扱いしない。

空欄、－だけの数、日本語変換中、未完の引用、未完の接続は未確定状態。保存・実行・対象変更・定義変更・モード変更の前に、確定できるか調べ、残るときはその欄と取消を示す。入力を取り消しても下書き全体を捨てない。一つの意味上の編集は一度で戻せる。拒否・取消・表示だけの変更で履歴を増やさない。

数の入力はASCII/全角の符号・数字・小数点を両モードで同じように扱う。－10、-10、１０、0.5、－0、途中の－、空欄、貼付け、IMEを試験する。非有限数は拒否する。－0は値として0と同じだが原文は利用者の明示的な整形まで保持する。式全体を勝手に数値へ畳み込まない。

保存・自動保存・再読込・生成HTMLで、本文ID・対象・イベント・定義・素材・下書きを検証する。未対応/不正なデータは現在の作品と下書きを保持し、「このファイルを開けませんでした」と理由を示す。勝手に削除・上書きしない。保存の内部識別子や検証方法は設計書で定め、制作画面に変更事情の表示を持ち込まない。

## 12 入口と画面

初めての利用は、空に近い作品、選べるキャラクター、自然なできごと見出し、目に見える動作一つ、動かす/止める/戻すが見えるところから始める。既に保存した表示や作品は尊重する。「かんたん」「くわしく」は案内量であり、使える言語や作品形式を変えない。

1366×768、1280×720、1024×768、狭幅、200％表示を実操作で調べる。手順/答えの編集でも本文を主要な領域として確保し、道具箱・定義一覧・ボタンに埋もれて切替ボタン自体の高さが約240pxとなって本文を押し出す不具合をなくす。大きな切替ボタンを固定的な小さな高さに戻し、本文が残るレイアウトにする。最低限、見出しと6行相当の本文、確定/取消、動かす作品への復帰が同時に到達できること。単にページ全体がスクロールできるだけで合格にしない。

作品画面の倍率と作業台の倍率を混同させず、全体表示・100％・元の編集位置へ戻る経路を示す。文字幅は実フォント・かな・漢字・絵文字・結合文字・ズームで確認し、単位や助詞が入力枠に隠れないようにする。

## 13 曖昧さと誤読の拒否例

以下は「日本語として間違い」と決めつける表ではない。意図が複数ある、情報が足りない、または未対応のときの契約である。

| 10秒後に右へ10歩動く | 10秒かけた移動 | 10秒待ってから右へ10歩動く形を提案 |
| 右へ10歩動く | 向きを勝手に右へ変える | 画面の右へ移動。向きも変えたいときだけ向く文 |

## 14 受入試験

全試験は実装された最終候補に対して行う。ここにある期待値を、候補の実測値で上書きしてPASSにしない。

- INTENT-CORPUS：既存仕様を読む前に独立に固定したCI-01〜CI-20（child-intent-corpus.md/json）を意図の判定基準とし、仕様に合わせて作文や期待動作を書き換えない。文法設計者の正解例だけで代用しない。受理、必要な確認、未対応を区別する
- ROLE-PERMUTE：表1.2の全順序・全対象形・かな形を生成し、同じ意味モデルとトレースを得る。重複役割・単位欠落のnegativeも行う
- JAPANESE-REVIEW：主語述語、助詞、修飾の係り先、接続、時制/相、名詞化を、日本語の文としてレビューする。構文解析PASSだけで代用しない
- ACTOR-SCOPE：省略対象、明示対象、自他の文型、複数対象の連文、枝/反復/定義の境界、分身、自分のデータ、名前指定の元個体を固定トレースで確認
- EVENT-ASPECT：押下1回、押し続け、解放、初期成立、初期不成立、押下中に開始、キーの自動反復、click連打、変化と状態の取り違えを確認
- EVENT-EDIT：見出しをコード/ブロック両方から変更し、ID・対象・絞り込み・本文・複数ハンドラー・保存を確認
- GENERATED-CLOSURE：本文・付録・ブロック・教材の全標準生成例が、登録済み文型/活用/名詞格だけで解析でき、同じ意味ASTへ戻る。未登録の連用形や任意名の不自然な活用を拒否
- PREDICATE-FORMS：全活用表をif/while/until/wait/not/andの文脈で往復。名詞/形容詞/状態述語の接続を混ぜたnegativeを含む
- LOGIC-SCOPE：全真理表、OR両方成立、短絡、左右評価順、入れ子、否定範囲、型エラー。falseと0/空文字/文字列を混同しない
- SENTENCE-SEQUENCE：1行複数節、複数文、if内の複数節、式や文字の読点、各節の1命令実行・選択・移動・注釈・undoを確認

### 将来の効果検証として子どもと行う評価

本作業の完成ゲートにはしない。実施は未着手。保護者・学校等の適切な同意と運用を整えたうえで、同じ説明と機器条件で行う。録画や個人情報収集は別途許可を得る。学年適合性の断定を先に置かない。

課題は、(a)右へ動かして別の人物に話させる、(b)四角を描く、(c)キーを押している間だけ動く、(d)点数で分ける、(e)持ち物へ挿入して表示する、(f)ジャンプをまとめて使う。まず場面だけ提示し、子どもが使いたい文・ブロックを作る。例文を見せる前の成功と、候補を見て成功したものを区別する。

測定項目は、意図した結果になったか、文をどう直したか、どこまでくり返すと思ったか、だれが動くと思ったか、理由を自分の言葉で説明できるか、詰まった箇所、必要な支援、取り消して回復できたか。誤ったプログラムが偶然見た目だけ一致した成功を数えない。

独立コーパスCI-01〜CI-20は文法を見る前に作成された設計資料であり、児童の実測作文ではない。コーパス原文をこの仕様に合うよう書き換えない。下表は「意図を満たす道筋」を評価するもので、作文候補の全文を無条件に構文解析できるという宣言ではない。

分類：直接＝定義した自然な文型で実行へつながる。構造化支援＝範囲/参照先等を原文上で示して確定する。要確認＝意図が複数ある/不足があるため、確認なしでは実行しない。未実装なので、全行の実行・往復検証はNOT_RUN。

| ID | 固定した意図 | 本仕様の道筋 | 受入で落としてはいけないこと |
|---|---|---|---|
| CI-01 | ねこだけ右移動、その後いぬが話す | 直接：明示対象＋画面方向＋そのあと＋使役の発言。1.1〜1.4 | 向きや発話者を変えない。同じ順次実行 |
| CI-02 | 省略主語を範囲で追う | 直接：見出しとsuiteの対象継承。条件内参照は変更しない。1.3 | 範囲移動で主体が変わる場合を見せる。空行で変えない |

| CI-20 | 画像と録音を使いオフライン保存再生 | 直接：背景変更/音の終了待ち/後続移動＋保存操作。8・11 | 資産ID、音と台詞、同名/未登録、playerとオフライン |

直接受理の割合だけを上げるため、曖昧なものを成功扱いにしない。一方、方向移動・継続状態・自然条件・名前付き引数など代表的な意図まで毎回低水準の命令列へ書き直させる実装も不合格。構造化支援は原文と範囲を保ち、候補を確定する少ない操作でコード/ブロックへつながることを実UIで確認する。
