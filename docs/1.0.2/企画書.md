# あかり1.0.2 企画書

## 子どもの作文から作品を動かす

あかり1.0.2は、子どもが思い描いた場面を、自分で主語・助詞・修飾語・述語を組み立てて書き、その文どおりに作品を動かせる環境にする。正解の命令文を暗記して写すことも、機械の用語を日本語らしく読ませることも、入口の中心にしない。ブロックはその作文を手で組み立てる道具とし、コードは同じ作文を直接書く道具とする。

「イメージする→文にする→動かす→結果と文を比べる→直す」を設計・評価の一周とする。「用意された文を読めた」だけでは達成としない。正しい日本語でも実行内容をまだ決められない文はある。その場合は、子どもの日本語を間違いと決めつけず、分かった部分を残し、足りない対象・量・範囲などを具体的に確かめる。

本書と仕様書・設計書は実装前の再設計案であり、実装済み・児童検証済みの報告ではない。表示上の製品名は「あかり1.0.2」。内容は言語・編集モデルを含む大きな改訂とする。

## 譲らない三点

1. できることを減らさない。既存の74命令・153ブロックスキーマ・260能力は全能力を追跡する基準にする。名前や内部構造の維持、件数の上限を意味しない。高度なデータ・計算・手順・素材・保存・実行・調査機能まで代替経路を保証する
2. 新しいコードとブロックは、全機能について双方向に意味が一致する。コード専用の高度機能や、読めない「コードをそのまま入れたブロック」で逃げない
3. 専用ブランチとdraft PRで止める。mainへの直接更新・マージ・自動マージ・リリース公開を行わない

文型や保存内部の構造は、この三点を最もよく達成する形にする。利用画面と教材は、いま作っている作品の言葉・動き・編集に集中させる。読めないファイルで現在の作品を壊さないための内部検証を行う。

## 設計の基本方針

語彙・読み・初期値の改善に加え、子どもが自分で文を組み立てて実行につなげるために、次を設計の本体にする。

- 「ねこは右へ10歩動く」「ねこは10歩右へ動く」「ねこを右へ10歩動かす」を、文節の役割から同じ動きとして読めるようにする
- 「前へ」と「右へ」、「右を向く」と「右に回る」、「1秒で」と「1秒後に」を区別する。短い語に置き換えるために動作を変えない
- 「もし点数が10より小さければ」「キーが押されているあいだ」のように、述語を正しく接続して条件を書けるようにする
- 「進んで、回る」「待ってから、進む」の接続と、字下げでまとまる範囲を、実際の順序・待機・くり返しへ結びつける
- 「いつ」「だれが」を、編集できる文の見出しとしてコードとブロックの両方に置く。選択欄だけに意味を隠さない
- 子どもの文が途中でも、入力したものを失わず、分かっている役割を示す。機械が意図を推測して勝手に実行しない
- 複数のキャラクターが登場する文を、明示された順番の一つの実行として扱えるようにする。別のキャラクターを書いたことを「書く場所が違う」で終わらせない

## 作文から始める八つの例

ここで示す作文は設計者が作った例であり、実際の児童の発話記録ではない。条件見出しの下は、コードでは字下げ、ブロックでは囲いに入れる。

| 思い描いた場面 | 基準版で必要になる表現 | 1.0.2で書く文と意味 |
|---|---|---|
| ねこだけを画面の右へ動かす | 横位置を横位置＋10にする | ねこを右へ10歩動かす。向きは変えない |
| ねこが向いている方へ進む | 10歩動く | ねこは前へ10歩進む。現在の向きを使う |
| 右を向いてから進む | 方向を0度にする／10歩動く | ねこは右を向いて、10歩進む。二つの命令を順に行う |
| 進む・待つの組を3回行う | 次のことを3回くり返す＋本文 | 10歩進んで、1秒待つことを3回くり返す。組全体が3回 |
| 点が足りたときだけ喜ぶ | もし 点数が10以上なら、次のことをする | もし点数が10点以上なら、／  ねこは「やった！」と言う。条件を調べるのは到達時の一度 |
| キーを押している間だけ進む | キーのイベント＋条件反復 | 「右」キーを押しているあいだ、ねこは右へ1秒に20歩の速さで動き続ける。保持・解放を表す一つの文で書く |
| リストの途中に傘を加える | 持ち物の2番目に「かさ」を挿入する | 持ち物の2番目に「かさ」を入れる。後ろの項目が一つずれる |
| ねこが動いて、その後いぬが話す | 別本文や通知の組立てが必要 | ねこを右へ10歩動かす。そのあと、いぬに「着いたよ」と言わせる。同じ実行の中で順番に行う |

「3回、10歩進んで、1秒待つ」は、進むだけか、待つまで含めるかが定まらない。そのまま実行せず、二つの囲い方を原文の横に示す。子どもが決めた範囲をコードとブロックの両方に残す。

## 国語としての根拠と限界

文部科学省『小学校学習指導要領（平成29年告示）解説 国語編』の第3・第4学年、本文83頁（PDF86頁）は、文を理解する場合だけでなく表現する場合にも、語句の役割と関係を意識することを扱っている。この考えを、主語と述語の対応、どの動作に量・方向・時間が係るか、文と文をつなぐ語、段落の範囲へ反映する。

出典：[文部科学省 国語編](https://www.mext.go.jp/component/a_menu/education/micro_detail/__icsFiles/afieldfile/2019/03/18/1387017_002.pdf#page=86)

これは本製品に対する推奨・認定でも、学習効果を示す調査でもない。「平仮名が多い」だけで国語教育上よいとも判定しない。教員による作文の確認と、実際の子どもが初見の場面を表現する試行を、機械試験と別に行う。

## ブロックは作文を組み立てる道具

目標は、同じ課題を作り、直し、結果を確かめるときにScratchより使いやすいこと。優位性は未検証であり、宣伝文句として断定しない。

各ブロックを「値を設定」「対象」「実行」のような見出しの寄せ集めにせず、一つの文として読めるようにする。「ねこを［右へ］［10歩］動かす」では、対象・方向・量を変えると、その部分の文と予告される動きが一緒に変わる。「どこに入るか」は色だけでなく、文中の穴と役割名で示す。数を入れる穴に条件を落としたときには、何が入る場所かを例で伝える。

検索はカテゴリ名の暗記を要求しない。「右に行きたい」「小さくしたい」「2番目に入れたい」のような制作の意図から候補へ進み、候補を入れる前に対象と変化を見られるようにする。検索で意味が近い候補が見つかることと、その文章をそのまま実行することは区別する。

作業台・作品画面・いまの文を同時に見られる範囲を確保する。手順編集のコード/ブロック切替ボタン自体が約240pxの高さになり、本文を押し出す不具合を解消する。すでに作った「ジャンプ」の手順は、「ジャンプ」で探して直接置けるようにする。値を直す、戻す、途中の文を入れ替える、間違いを取り消す操作まで含めて比較する。

## 学びが進んでも同じ作品を育てる

初めは、対象・できごと・目に見える変化・順番を使う。次にくり返しと条件、点数やリスト、まとまった手順、答えを求める定義、多くの登場人物、分身、画像・音を組み合わせる。この順番は案内の順番であり、能力を使えなくする設定ではない。

条件の文は、数の比較やキー・接触の状態をそのまま書く。初心者に毎回「はい／いいえ」を挟ませない。条件の答えをデータとして保存する場合は、「あてはまる／あてはまらない」を説明付きで扱い、文字列・0・未入力とは区別する。正式な真偽型、論理演算、式への組込みは維持する。

手順は「命令をまとめて行うもの」、答えを求める定義は「値を求めて式の中で使うもの」とする。後者は乱数・状態・外部値を読めるため、「同じ入力なら必ず同じ答え」とは説明しない。外の値を書き換えることや、待つこと・描画することなどの禁止は維持する。

## 完成の判定

1. 独立した意図コーパスで、作文が受理されるか、曖昧なら適切な確認になるかを調べる
2. 受理した文の対象・順番・時間・条件・範囲が、子どもの意図に対応する固定トレースと一致することを確認する
3. 全能力台帳についてコード・ブロックから作成、変更、保存、再読込、実行へ到達することを確認する
4. 実ブラウザーでクリック・ドラッグ・キーボード・IME・取消・復元・画面幅を調べる
5. 未実施・失敗・環境による停止をPASSに混ぜず、最終コミットの証拠をdraft PRに記録する

文書・設計・実装・静的検証はクラウドで行う。ユーザーのPCは許可されたChromeでの独立した動的確認だけに使用する。本作業では製品ソースを変更していない。
