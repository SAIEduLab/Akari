# Release audit externalization

Historical phase-1 relocation record. Byte-for-byte runtime and product-diff invariance below applies only to H0 → HA. Current language/editing/version changes are reviewed in `records/phase4-semantic-review.md`; `lib/completed-runtime-contract.mjs` now checks exact runtime equality with the verified 1.0.1 checkpoint; the prior identifier and version correspondence remains recorded as history.

The migration baseline is public commit `41d787b664ed00467bf55881c419ba4f3727add9`, product blob `eef9f71d0721c376e73885268726f5ee341c5a5a`.

`manifests/externalization-map.json` inventories every moved function, original line range, normalized body hash, assertion call (including its fixture/expected expression), local binding, external dependency and product reference. `suites/` preserves the function bodies verbatim except CRLF-to-LF transport normalization. Generated IDs are expanded in `product-tests.json` and the map, and anchored by the complete baseline ID-set digest. The release aggregator and its exact invocation order are also preserved as an inventory source; the host executes each constituent suite in a fresh offline browser context.

The 12 suites cover 884 stable IDs. The former entry points comprise 13 function declarations, nine public function references, and `?selftest=1`; results used `selfTestReport`, `data-selftest-failed` and the report fields. No product caller invokes those functions. AST binding reference analysis found only the audit-to-audit calls, diagnostic exports and the dedicated bootstrap call. Local fixtures, helper assertions, literals and report aggregation move with their enclosing functions. No product parser or runtime is copied.

All other dependencies are shared product functions/data. The map records their product reference sites, including object shorthand/destructuring rather than only call expressions. Standalone export stringifies `createAkariRuntime`, `createAkariStageView`, and `mountAkariPlayer`; all three remain byte-for-byte unchanged. Normal bootstrap, editing, validation, saving, runtime limits, executable packing and these indirect export dependencies remain in the product.

The adapter uses 55 existing API references. `AKARI_RUNTIME` is a two-member view of the existing `restoreExecutable` and `EXECUTABLE_VERSION` APIs. The remaining 29 named references form `Akari09.diagnostics`, a frozen, finite reference object; no global app-state setter, audit dispatch, fixture, expected value or conditional audit mode is added. They are the existing validation boundaries, geometry/palette calculations, canonical scalar/runtime helpers and product constants identified in the map. GUI replacement would lose the existing direct boundary/assertion coverage (including error class identity, metadata validation and pure geometry); GUI behavior remains covered by the separate browser suites. Constants are observed from the product rather than duplicated as new expected fixtures. This API addition exposes existing implementations without bypassing validation or changing their behavior.

GA-STATIC: body hashes, complete ID sets, capability/0.8 references, product absence, snapshot hashes, fixed fixture provenance and byte/line measurements. GA-EXEC: actual HTML execution, same-candidate comparison, harness negatives, independent fresh contexts, normal GUI save/export/offline checks and all existing browser groups. HYBRID: dependency classification, API necessity, assertion/expectation preservation and absence of coverage weakening require source review in addition to these checks. This migration does not change the language, parser, save format or block schema.

On Windows with `core.autocrlf=true`, checkout bytes differ from Git blob bytes. Measurements report both; fixed baseline verification checks the canonical blob against the unchanged provenance manifest and separately records executed checkout hashes. Fixed fixtures and their embedded execution/report path remain unchanged. The existing runner's shutdown now checks `signalCode` and installs its exit listener before killing the browser: a signal-terminated Windows process has null `exitCode` even after exit. This fixes cleanup without changing test launch, collection or baseline guarantees. Linux CI continues to verify exact fixture bytes through the existing workflow.

Migration comparison and final local results are recorded under `audit/records/`; detailed ephemeral reports live in ignored `audit-evidence/`. Historical comparison is evidence only for its named candidate, not a PASS for future heads. Final release/Ready evaluation still requires every applicable audit and SEMANTIC review.
