# Phase-2 source review

Historical record only. Current inline/edit/save behavior and completed semantic review are described in `phase4-semantic-review.md`; statements below about pending phase 3 are not the current acceptance contract.

Scope: language/parser only, relative to public phase-1 commit `05789beae52221fb8aa259f1de0f778c236afbf9`. Execution evidence and final head binding are generated under `audit-evidence/phase2/`; this review does not claim an unexecuted test passed.

- `ExpressionParser.predicate` retains the existing successful parse, selects a fixed comparison terminal, and fills existing CompareExpression left/right. The existing additive parser determines the normal left operand and its following が; this protects compounds such as キーが押されている and マウスが押されている on either side. Reverse comparisons require one outer より and the fixed が大きい/が小さい ending. It does not add global name breaks or consult registered symbols/current values. Depth is inherited and expression-tree depth validation remains. Logical order/short circuiting are unchanged.
- `readBlockHead08` extends fixed terminal spellings and indented headers. It does not parse inline bodies or alter block association. The omitted-if short-header family follows the explicit specification replacement in `language-transition.json`; every header still requires a nonempty indented body.
- `readConditionClause07` changes only recognized final connective positions. New short connectors have an enumerated list. Reverse comparisons require the existing condition wrapper for while/until; arbitrary connective conjugation is not introduced.
- `surfaceMask09` scans once per selected statement/frame; quotes, exact names and bracketed phrases hide internal markers with equal-length placeholders. It does not normalize or rearrange the user's original source. `readSurfaceStatement09` selects from fixed statement suffixes, role markers and at most the two specified phrase orders. Regex captures point back into the original compact expression text. Legacy source normalization and Script.source remain the existing mechanisms. Fine-grained original UTF-16 role spans and UI editing are still phase 3.
- Data targets reuse parseTargetPrefix. Their grammatical shape is validated before existing semantic analysis. Omitted/multiple roles cannot be filled from context. List destination/index remains one phrase; coordinates require X/Y labels; durations, angle and frequency units are explicit. The `だけ` marker in new increment/decrement frames requires quoting a same-ending name. Existing accepted bare names elsewhere are preserved.
- All lowerings use existing kind/op/fields. No new runtime/schema/opcode or exported API is added. Coordinates and glide argument order are X/Y and T/X/Y, respectively; tone is F/T; comparison is X/Y. Binding checks, mutation, error order, waiting and PRNG sampling execute in the unchanged runtime. ForEach remains a snapshot with readonly binder; Ask remains one task-owned question.
- The old coordinate/header dispatch is replaced by the shared extended dispatch, avoiding a second competing canonical implementation. Other existing forms retain their existing parser routes. There is no token permutation search, source-wide synonym replacement, new meaning node, target inference or runtime branch for an alias.
- The origin map preserves all 884 IDs and body hashes. Only the obsolete current `08 indent reject 12` is retired through the recorded JPF replacement; 883 core IDs remain, with an explicit suite-hash override. All 122 fixed-0.8 capability entries retain their required current IDs. Language fixtures and expectations live outside Akari.html. Validators reject missing/duplicate/extra cases and forged status/snapshot counts. DEFERRED remains distinct from PASS.
- New audit claims are split between GA-STATIC (sets, hashes, schema/runtime/API invariance), GA-EXEC (actual candidate parser/runtime/browser, errors and performance), and HYBRID/SEMANTIC (role interpretation, old/new boundary and nonweakening). Naturalness has a design rationale only; there was no user study.

- Additional near-limit malformed input exposed quadratic backtracking in the initial multi-capture comparison and slide patterns: repeated `1秒で` without a destination, and repeated `aが` with a nonmatching comparison terminal. The correction selects terminals before parsing operands and checks mandatory outer duration/destination, frequency and input markers before capture matching. It does not raise limits or the five-second worker timeout. The permanent boundary suite now has 90 measurements, including six late-failure families and near-limit cases on both HA and candidate. Atomic sensor operands are tested in both comparison positions to prevent an overly broad marker-count rejection.

Remaining acceptance boundary: phase-3 inline/edit/save/version work, final project-wide audit and remote Actions are not discharged by phase-2 parser evidence. The guarantee ledger records pending replacement of old-version-only or mixed save tests, preserving malformed-data and state-protection guarantees. Fixed-0.8 quality/capability comparison remains mandatory through 1.0.0 completion. Only afterward does the fixed checkpoint move to the completed 1.0.0 snapshot. No final HF measurement is claimed.
