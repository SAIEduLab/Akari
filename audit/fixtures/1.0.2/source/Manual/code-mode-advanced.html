1. あかりの実行モデルを理解する

上級では、コードの文型だけでなく「いつ、どの本文が、どの順番で進むか」を意識します。

本文は対象×できごとごと「動かすもの」と「できごと」の組合せに、1つの本文を登録します。
開始処理の順序開始時は、画面、その後に部品の登録順で処理が作られます。
命令単位で進む複数の処理は命令単位で順番に進みます。
待機は処理ごとある処理が待っていても、待っていないほかの処理は進みます。
「同時に見える」と「同じ瞬間に実行する」は別です。 あかりでは、複数処理が命令単位で交互に進むため、共有する作品データを書き換える処理では順序を意識して設計します。

開始本文が終わっても作品は動き続ける

「開始したとき」の本文が終わっても、作品全体が自動停止するわけではありません。「■ 止める」まで、クリック、キー、知らせなどの新しいできごとを受け付けます。

2. 名前解決とスコープ

同じ名前が複数の場所にある場合、修飾していない名前は次の優先順位で読まれます。

1
反復の項目名
「各要素を項目として」のような、現在の反復内だけの読み取り専用名。
2
局所データ
動作・計算の中で作った局所変数・局所リスト。
3
引数
動作・計算が受け取った値。
4
個体データ
現在の部品・キャラクター自身が持つ変数・リスト。
5
作品データ
作品全体で共有する変数・リスト。

同じ名前がある例

個体にも作品にも「点数」がある状態で、単に 点数 と書くと、現在の個体側が先に見つかります。作品全体の値を必ず読みたいときは明示します。

自分の点数に1を足す。
作品の点数に1を足す。
大きな作品ほど所属を明示する。 同名データを使う可能性がある場所では、自分の と 作品の を書いておくと、後からデータを追加しても意味が変わりにくくなります。

3. 名前を曖昧にしない

例を実行するには、作品変数「手がかり」（文字の「北」）と「端」（数の0）を先に作ります。ここで【 】は名前を区切る印で、データの名前に付けて登録する文字ではありません。

名前は1〜32文字で、空白・括弧・制御文字・予約語などは使えません。普通の名前はそのまま書けますが、文法上の語とぶつかる名前は区切りを明示します。

もし 【手がかり】が「北」と同じなら、「北へ進もう」と言う。
作品の【端】を0にする。

助詞や演算子を含む名前、数字で始まる名前、「端」「空白」のような固定語と同じ名前は、【 】 で囲めます。

【 】と所属は役割が違う

書き方役割
【手がかり】名前の区切りを明確にする。
自分の点数個体データを明示する。
作品の点数作品データを明示する。
作品の【手がかり】区切りと所属の両方を明示する。

4. 「動作」を設計する

動作は、複数の命令を1つの名前にまとめる仕組みです。呼び出した個体を対象として実行されるため、キャラクター固有の動きを部品化するのに向いています。

動作「ジャンプ」／引数「高さ」
縦位置を縦位置－高さにする。
0.2秒待つ。
縦位置を縦位置＋高さにする。
ジャンプ（30）を実行する。

引数は値渡し

引数は呼出し時の値として渡されます。リストも複製して渡されるため、受け取った引数リストを動作内で変更しても、呼出し元のリストそのものを直接変更することにはなりません。

局所データを使う

動作・計算では、本文の先頭で局所変数や局所リストを作れます。途中計算の値や一時的な作業用データは、作品データを増やさず局所データへ閉じ込めると整理しやすくなります。

作業値という変数を作り、初期値を0にする。
結果というリストを作る。
動作の呼出しが深くなりすぎると実行時エラーになります。呼出し深さの上限は64です。再帰的・相互再帰的な設計では特に注意します。

5. 「計算」を副作用のない処理として設計する

計算は、値を計算して返すための定義です。動作と違い、外部へ副作用を起こす命令や待機は使えません。

計算でできること

  • 引数・局所変数・局所リストを使う。
  • 条件分岐や反復を使う。
  • 式を評価し、最後に値を返す。
  • 外部の値を読み取って計算に使う。

計算でしてはいけないこと

  • 作品データ・個体データなど外部データの変更。
  • 移動・見た目・ペン・音・クローンなど外部へ影響する命令。
  • 「待つ」、質問、知らせ、動作呼出しなどの副作用や待機。
計算「合計値」／引数「数一覧」
合計という変数を作り、初期値を0にする。
数一覧の各要素を項目として、次のことをくり返す。
  合計に項目を足す。
合計を返す。

計算の最後には「〜を返す」を1つ置きます。返却がない計算は正しい定義になりません。

計算には実行量の上限がある

計算は、止まらない計算を防ぐため、式評価や反復を含めた処理量に上限があります。現行の functionOps は100,000です。また、計算の呼出し深さは64です。

設計の目安： 画面や音を変える処理は「動作」、値を求める処理は「計算」に分けると、役割が明確になります。

6. 複数処理と待機を設計する

クリック・キー・知らせなどから複数の処理が動く作品では、共有データと待機の関係が重要です。

待つ処理と進む処理

「準備中」と言う。
2秒待つ。
「完了」と言う。

この本文が2秒待っている間も、別の実行中処理は進めます。したがって、作品データを複数処理から変更する場合は、「待っている間に別処理が値を変える」ことを前提にします。

共有データを使うときの考え方

  • 初期化は「開始したとき」へ集める。
  • 同じ作品変数を複数処理が更新するなら、どのイベントがいつ更新するかを決める。
  • 処理間の順序が必要なら、知らせと「受け手の処理が終わるまで待つ」を使う。
  • 個体ごとに独立させたい値は作品データではなく個体データへ置く。
「待つ」を同期処理の代わりに秒数で調整する設計は壊れやすくなります。完了順序が重要な処理は、知らせや状態条件で明示します。

7. 知らせの同期を使い分ける

非同期に開始する

「演出開始」と知らせる。
「次の処理」と言う。

通常の「知らせる」は受け手を起動し、送信側は次へ進みます。

直接の受け手を待つ

「演出開始」と知らせ、受け手の処理が終わるまで待つ。
「演出完了」と言う。

この形は、その通知によって直接起動した処理の終了を待ちます。受け手が途中で別の知らせを通常送信した場合、その先の処理まで自動的に待つわけではありません。

自己再通知に注意。 「知らせを受けたとき」の本文で、条件なしに同じ知らせを送り直すと再通知が続きます。メッセージ名や条件を分けて循環を避けます。

8. クローンを実行時の個体として使う

クローンは、キャラクターを実行中だけ複製する仕組みです。

自分のクローンを作る。
「星」のクローンを作る。

複製されるもの・共有するもの

複製される個体データと見た目。
共有される作品データ。

クローンが作られると、そのクローンでは「クローンされたとき」の本文が新しく起動します。

クローンされたとき
10歩動く。
1秒待つ。
このクローンを削除する。
実行中に作られたクローンや、実行によって変わった個体状態は作品ファイルの保存内容には反映されません。次の実行は初期状態から始まります。

クローン数の現行上限は500です。大量生成する処理では、削除条件を必ず設けます。

9. 停止命令を使い分ける

次は三つの選択肢です。全部を続けて使う例ではありません。目的に合う一つを本文へ入れます。

このスクリプトを止める。
ほかのスクリプトを止める。
すべてを止める。
命令用途
このスクリプトを止める現在実行している処理だけを終了する。
ほかのスクリプトを止める現在の処理を残し、ほかの実行中処理を止める。
すべてを止める作品全体の実行を停止する。

反復だけを途中で抜けたい場合は、停止命令ではなく このくり返しを終える。 を使います。次の回へ飛ばしたい場合は 次のくり返しへ進む。 を使います。

10. 失敗記録から原因を追う

実行エラーが起きると処理は一時停止し、失敗した瞬間の情報を記録します。大きな作品では、表示されたエラー文だけでなく記録の中身を見ます。

失敗記録に残る情報

  • 失敗した動作・計算自身の行と命令。
  • 呼出し順。
  • 引数。
  • 局所変数・局所リスト。
  • 作品データと個体データ。

「全文」を使うと、長い値をページごとに、リストを要素番号ごとに確認できます。実行を続けて現在値が変わっても、失敗時の記録は変わりません。

記録の保持

失敗記録は直近20件以内、かつ記録JSON合計8,388,608文字を目安に古いものから削除されます。最新1件はこの長さを超えても保持されます。「停止」と次回実行で記録は消えます。

失敗した処理そのものは終了します。原因を修正したあとは、その処理を途中から再開するのではなく、改めて実行します。

11. エラーコードの種類を読む

エラーコードの先頭文字を見ると、どの段階の問題かを切り分けやすくなります。

先頭意味主な確認先
Fファイル・保存・読込み作品ファイル、素材、保存形式
N / P文字・文法名前の書き方、字下げ、文型
S参照・意味未登録名、対象制約、引数数、計算の副作用
R実行時型、値の範囲、0除算、リスト範囲、呼出し深さ
X書き出し形式単体HTML生成時の条件

文法・名前・対象の問題はできるだけ実行前に「作品チェック」で検出されます。一方、値の型や範囲など実際の値が必要な問題は実行時に検出されることがあります。

13. 保存・復元・書き出しの契約を理解する

.akari.md は読むための本文と復元用データを持つ

「保存」で作る .akari.md には、コード・初期データ・部品・素材一覧と、末尾の復元用データが含まれます。Markdown部分は人が読むためのもので、直接編集する場所ではありません。

本文と復元データが一致しない作品ファイルは F512 で拒否され、現在開いている作品は保たれます。

1.0.2の保存・実行形式

製品版は1.0.2、言語・runtime版は1.0.0、保存・実行形式番号は3です。1.0.0・1.0.1の作品も開けます。1.0.2内での往復と不正データ検証を保証します。

書き出し

下書きの定義を登録し、作品全体の文法・参照検査に合格してから書き出します。操作順とファイルの使い分けは総合ガイドを参照してください。

「書き出し」は、編集機能を含まない単体HTMLを作ります。コード表示・ブロック表示のどちらからでも同じ確定済み本文を検査し、実行処理と素材を含めます。書き出したHTMLの実行にブロックエディタや外部ファイルは必要ありません。

終了前の保存

作業内容や動作・計算の未登録下書きは、自動保存されません。下書きを残すには定義を登録したうえで、作品ファイルを保存します。保存前に終了した場合は復元できません。

あかり本体は外部通信や外部スクリプトの読込みを行わない構成です。作品の保存・書き出しも、現行仕様ではローカルで完結する前提です。

14. 大きな作品を壊れにくく設計する

別の語順でも、値を調べる順番は同じ

横・縦の句を逆に書いても、値は横、縦の順に調べます。「滑る」は時間、横、縦、「音」は周波数、時間の順です。乱数を含む式でも、文に書いた順へ評価を入れ替えるわけではありません。単語を自由に並べ替えられる機能ではなく、役割を示す句の決まった並びを受け付けます。

上級では「書ける」だけでなく、変更しても意味が崩れにくい構造を作ることが重要です。

おすすめの分け方

できごとで入口を分ける→ 動作へ副作用をまとめる→ 計算へ値計算をまとめる→ 知らせで処理を接続する→ 作品データを最小限にする

設計チェック

  • 共有する必要のない値を作品データにしていないか。
  • 同名データがある場所では 自分の / 作品の を明示しているか。
  • 外部へ影響する処理と値計算を、動作と計算で分離できているか。
  • 秒数待機だけで処理順を合わせていないか。
  • 知らせが循環していないか。
  • クローンに削除条件があるか。
  • 再帰・反復・同時処理が上限へ近づかないか。
  • 失敗時に追えるよう、処理を小さな動作・計算へ分けられているか。
上級の到達点： 文法だけでなく、スコープ、実行順序、副作用、同期、保存形式、上限、失敗時の観測まで含めて作品を設計できれば、あかり 1.0.2 のコードモードを実践的に扱える状態です。
